## 2. scons 与 RT-Thread 的关系

**scons 不是 RT-Thread 专属**。scons 是一个通用构建工具（Python 实现，定位类似 make/CMake），可以构建任何工程。RT-Thread 官方把 SCons 选作其标准构建体系（`SConstruct` + `SConscript` + `rt-thread/tools/building.py`），所以本仓库的三个 RT-Thread 板才会出现 scons 工程文件。

推论：

- **RT-Thread 板（display / sensor / remote）**：需要 scons（版本要求见 §3）。
- **cpr-head-board / cpr-raster-board**：裸机 Makefile 工程，**完全不需要 scons**，用 `make` 构建（见 §5）。

## 3. scons 安装（项目局部，不动环境变量）

本仓库的 `rt-thread/tools/building.py` 与 **SCons 4.5+ 不兼容**（`TypeError: can only concatenate deque (not "list") to deque`，已实测 4.11.1 复现），因此 **必须锁定 scons 4.4.x**。

### 3.1 Windows：项目目录 venv（推荐，已实测）

在仓库根目录创建自带 Python 的虚拟环境安装，不修改 PATH 与任何环境变量：

```powershell
cd C:\Users\18452\Documents\github-nights\cpr-assessment-training-machine
C:\Users\18452\AppData\Local\Programs\Python\Python313\python.exe -m venv .venv-scons
.venv-scons\Scripts\python.exe -m pip install scons==4.4.0
.venv-scons\Scripts\scons.exe --version    # 应显示 4.4.0
```

调用时写全路径（无全局 `scons` 命令，这是刻意的）：

```powershell
..\.venv-scons\Scripts\scons.exe --target=cmake
```

安装位置：`.venv-scons\Lib\site-packages\SCons`，与系统 Python、RT-Thread Studio 自带环境互相隔离。

### 3.2 关于 RT-Thread Studio 的 env-windows

`C:\RT-ThreadStudio\env-windows` 是 RT-Thread Studio 自带的 ENV 整合环境（scons + Kconfig + 包管理 + 工具链），其内部 `.venv\Scripts\scons.exe` 为 **4.11.1**，与本仓库的 building.py 不兼容，**不能用于本仓库的 scons 构建**（可用于 menuconfig / 包管理）。

### 3.3 WSL（备用）

```bash
pip3 install scons==4.4.0     # WSL Python 若有 PEP 668 限制需先解除或加 --break-system-packages
export RTT_EXEC_PATH=/usr/bin # 指向 arm-none-eabi-gcc 所在目录
export RTT_CC=gcc
```

## 4. scons 使用（RT-Thread 板）

以 `cpr-display-main-board` 为例（sensor / remote 同构）：

```powershell
cd cpr-display-main-board
set RTT_EXEC_PATH=C:\ST\STM32CubeCLT_1.18.0\GNU-tools-for-STM32\bin
set RTT_CC=gcc
..\.venv-scons\Scripts\scons.exe --target=cmake   # 生成 CMakeLists.txt，随后用 CMake Tools 构建
```

| 命令 | 作用 | 说明 |
|------|------|------|
| `scons --menuconfig` | Kconfig 配置 | 修改 rtconfig.h |
| `scons --target=cmake` | 生成 CMakeLists.txt | **dry-run，不会真正编译**，控制台 CC/LINK 为模拟输出 |
| `scons` | 直接构建 | **当前不可用**：`drivers/`、`applications/`、`libraries/` 缺 SConscript，报 `stm32f1xx_hal.h: No such file or directory` |

注意事项：

- 不设 `RTT_EXEC_PATH` 会报 `Cannot found toolchain directory, please check RTT_CC and RTT_EXEC_PATH`。
- `--target=cmake` 生成的 CMakeLists.txt 不完整（缺 HAL/CMSIS 头路径、编译宏与约 90 个源文件），需要按 `Debug/makefile` 补齐补丁段后才能用 CMake Tools 构建（完整补丁见 `docs/` 之外的 VSCode 嵌入式开发笔记，或直接对照 `cpr-display-main-board/Debug/makefile` 核对 `-I` / `-D` 清单）。

## 5. cpr-head-board 与 cpr-raster-board 编译

### 5.1 代码形态说明

两板结构同构：**STM32F103C6T6 裸机**，`Drivers/stm32f103x6.h` 为**自研最小寄存器定义头**（仅定义实际用到的外设寄存器），`Drivers/startup_stm32f103c6.s` 为启动文件，`Linker/stm32f103c6_flash.ld` 为链接脚本，全部源码在 `Src/`。

> [!注意] 术语澄清
> 仓库中**没有** STM32F10x 标准外设库（SPL）和 HAL 的源码——代码是寄存器级直操 + 自研头文件，不依赖任何厂商外设库。口头说的"标准库"若指 SPL，与代码现状不符。

### 5.2 前置工具

| 工具 | 用途 | Windows 侧来源 |
|------|------|---------------|
| arm-none-eabi-gcc | 编译链接 | STM32CubeCLT（已在 PATH） |
| GNU Make | 构建入口 | `C:\RT-ThreadStudio\env-windows\tools\BuildTools\2.12-20190422-1053\bin\make.exe`（不在 PATH，用全路径调用） |
| OpenOCD（可选） | `make flash` 烧录 | 未安装；可用 STM32CubeProgrammer 替代（见 5.4） |

WSL 侧已有 arm-none-eabi-gcc 与 make，可直接构建。

### 5.3 编译命令（两板相同，仅目标名不同）

```powershell
cd C:\Users\18452\Documents\github-nights\cpr-assessment-training-machine\cpr-head-board
C:\RT-ThreadStudio\env-windows\tools\BuildTools\2.12-20190422-1053\bin\make.exe        # 产出 build/cpr-head-board.elf/.bin
C:\RT-ThreadStudio\env-windows\tools\BuildTools\2.12-20190422-1053\bin\make.exe clean   # 清理
```

`cpr-raster-board` 同理，把目录换掉即可（目标名 `cpr-raster-board`）。

实测结果（2026-11-13，arm-none-eabi-gcc 14.2.1）：

| 板 | text | data | bss | 产物 |
|----|------|------|-----|------|
| cpr-head-board | 4232 | 12 | 2236 | `build/cpr-head-board.elf` / `.bin` |
| cpr-raster-board | 3092 | 12 | 1668 | `build/cpr-raster-board.elf` / `.bin` |

### 5.4 烧录

Makefile 自带的 `make flash` 通过 OpenOCD + ST-Link 烧录：

```text
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
    -c "program build/<target>.bin 0x08000000 verify reset exit"
```

未安装 OpenOCD 时，用 STM32CubeProgrammer（CubeCLT 自带，已在 PATH）等价替代：

```powershell
STM32_Programmer_CLI -c port=SWD -w build\cpr-head-board.bin 0x08000000 -v -rst
```

### 5.5 在 VSCode 中编译（raster / head 板）

用 VSCode 打开**板级目录**（如 `cpr-head-board`，让 `${workspaceFolder}` 指向板根）。raster 板同理，仅二进制名换成 `cpr-raster-board.bin`。

**方式一：tasks.json（推荐，路径可控）**

在板级目录新建 `.vscode/tasks.json`：

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "build",
      "type": "shell",
      "command": "C:\\RT-ThreadStudio\\env-windows\\tools\\BuildTools\\2.12-20190422-1053\\bin\\make.exe",
      "options": { "cwd": "${workspaceFolder}" },
      "group": { "kind": "build", "isDefault": true },
      "problemMatcher": ["$gcc"]
    },
    {
      "label": "clean",
      "type": "shell",
      "command": "C:\\RT-ThreadStudio\\env-windows\\tools\\BuildTools\\2.12-20190422-1053\\bin\\make.exe",
      "args": ["clean"],
      "options": { "cwd": "${workspaceFolder}" },
      "problemMatcher": []
    },
    {
      "label": "flash",
      "type": "shell",
      "command": "STM32_Programmer_CLI",
      "args": ["-c", "port=SWD", "-w", "build/cpr-head-board.bin", "0x08000000", "-v", "-rst"],
      "options": { "cwd": "${workspaceFolder}" },
      "problemMatcher": []
    }
  ]
}
```

使用：`Ctrl+Shift+B` 直接构建；`Ctrl+Shift+P` → **Tasks: Run Task** 选择 `clean` / `flash`。

**方式二：Makefile Tools 插件**（已安装 `ms-vscode.makefile-tools`）：

打开板级目录后 `Ctrl+Shift+P` → **Makefile: Configure**，之后用状态栏 Build 按钮构建。make 不在 PATH 时，在用户/工作区设置中指定：

```json
"makefile.makePath": "C:\\RT-ThreadStudio\\env-windows\\tools\\BuildTools\\2.12-20190422-1053\\bin\\make.exe"
```

**IntelliSense（可选）**：新建 `.vscode/c_cpp_properties.json` 让补全认识头文件：

```json
{
  "configurations": [
    {
      "name": "STM32F103C6",
      "includePath": ["${workspaceFolder}/Inc", "${workspaceFolder}/Drivers"],
      "defines": ["STM32F103x6"],
      "compilerPath": "C:/ST/STM32CubeCLT_1.18.0/GNU-tools-for-STM32/bin/arm-none-eabi-gcc.exe",
      "cStandard": "c11"
    }
  ],
  "version": 4
}
```

> 注意：以上 `.vscode/*` 配置含本机绝对路径（BuildTools / CubeCLT 安装位置），建议只作本地使用，不纳入 git 跟踪；换机器时按实际安装路径修改。
