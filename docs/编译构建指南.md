# 编译构建指南（cpr-head-board / cpr-raster-board）

> 适用对象：本仓库一切协作者（人类开发者与 AI Agent）。
> 范围：cpr-display-main-board / cpr-remote-device / cpr-sensor-board 三个 RT-Thread 板在 RT-Thread Studio 中编译，不在本文范围。本文只覆盖 cpr-head-board 与 cpr-raster-board 两块裸机板的 **CMake 编译**。
> 创建：2026-11-13，全部命令经 Windows 实测。

## 1. 两板构建体系

| 子工程 | MCU | 代码形态 | 构建体系 | 工具链 |
|--------|-----|---------|---------|--------|
| cpr-head-board | STM32F103C6T6 | 裸机 | CMake（主）+ Makefile（备） | arm-none-eabi-gcc |
| cpr-raster-board | STM32F103C6T6 | 裸机 | CMake（主）+ Makefile（备） | arm-none-eabi-gcc |

两板结构同构：`Drivers/stm32f103x6.h` 自研最小寄存器定义头、`Drivers/startup_stm32f103c6.s` 启动文件、`Linker/stm32f103c6_flash.ld` 链接脚本、源码在 `Src/`、CMakeLists.txt 在板级目录。

> 注意：仓库中**没有** STM32F10x 标准外设库（SPL）和 HAL 的源码——代码是寄存器级直操 + 自研头文件。口头说的"标准库"若指 SPL，与代码现状不符。

## 3. CMake 编译

### 3.1 命令行

```powershell
cd C:\Users\18452\Documents\github-nights\cpr-assessment-training-machine
cmake -S cpr-head-board -B cpr-head-board/build -G Ninja
cmake --build cpr-head-board/build
```

raster 板把目录名换成 `cpr-raster-board` 即可。

产物固定在各板自己的 `build/` 目录（如 `cpr-head-board/build/cpr-head-board.elf/.bin/.map`），**不会出现在项目根目录**：

- `CMakeLists.txt` 位于板级目录，构建目录指向板内 `build/`；
- 根目录 `.vscode/settings.json` 配置了 `"cmake.buildDirectory": "${cmake.sourceDirectory}/build"`，VSCode CMake Tools 同样遵守该约定。

实测结果（2026-11-13，arm-none-eabi-gcc 13.3.1）：

| 板 | text | data | bss | 产物 |
|----|------|------|-----|------|
| cpr-head-board | 4020 | 12 | 2236 | `cpr-head-board/build/cpr-head-board.elf` |
| cpr-raster-board | 3024 | 12 | 1668 | `cpr-raster-board/build/cpr-raster-board.elf` |

### 3.2 VSCode CMake Tools

1. VSCode 打开板级目录（推荐），或打开项目根目录；
2. `Ctrl+Shift+P` → **CMake: Configure**，Kit 选择 `GCC 13.3.1 arm-none-eabi`（STM32CubeCLT 自带）；
3. `Ctrl+Shift+P` → **CMake: Build**（或状态栏 Build 按钮）。

> 根目录工作区：CMake Tools 首次 Configure 会询问源码目录（仓库内有多个 CMakeLists.txt），选对应板级目录即可；切换板子时用 **CMake: Change Source Directory** 重新指定。

### 3.3 烧录

CMake 一键烧录（构建后执行，内部调用 OpenOCD + ST-Link）：

```powershell
cmake --build cpr-head-board/build --target flash
```

备选（STM32CubeProgrammer，不依赖 OpenOCD）：

```powershell
STM32_Programmer_CLI -c port=SWD -w cpr-head-board\build\cpr-head-board.bin 0x08000000 -v -rst
```

### 3.4 调试（简述）

Cortex-Debug（已装）+ OpenOCD + arm-none-eabi-gdb；`C:\ST\STM32CubeCLT_1.18.0\STMicroelectronics_CMSIS_SVD\STM32F103.svd` 可配置到 Peripheral Viewer 查看外设寄存器。launch.json 调试配置另行补充。

## 4. 备选：Makefile

两板保留原有 Makefile（已做路径锚定，产物同样在板内 `build/`）：

```powershell
C:\RT-ThreadStudio\env-windows\tools\BuildTools\2.12-20190422-1053\bin\make.exe -C cpr-head-board
```

> 注意：CMake 与 Makefile 共用板内 `build/` 目录且产物同名，不要交替混用两套构建；`make clean` 会删除整个 `build/`（含 CMake 缓存，之后需重新 Configure）。

## 5. 注意事项与已知漂移

1. **cpr-raster-board 已迁移**：2026-10-21 起（提交 `0776a4b`）由 STM8S + IAR EWSTM8 重构为 STM32F103C6T6 裸机。README 与 AGENTS.md 中"STM8S 裸机 (IAR)"、`MDK_Project/raster_project.ewp` 等为历史描述，当前工作区已无 `.ewp` 工程文件，勿据此搭建 IAR 环境。
2. **OpenOCD PATH**：实测安装于 `C:\ST\OpenOCD-20240916-0.12.0\bin`。执行 `openocd --version` 若报"不是内部或外部命令"，把该目录加入用户 PATH（或在 flash 时用全路径）。
3. **产物不入库**：各板 `build/` 目录已被 `.gitignore` 忽略，构建产物（.elf/.bin/.map/CMake 缓存）一律不提交。
4. **RT-Thread 工具不再需要**：scons、`.venv-scons` 等仅服务 RT-Thread 板的 SCons 构建；RTT 三板在 RT-Thread Studio 中编译，`.venv-scons` 可删除。
