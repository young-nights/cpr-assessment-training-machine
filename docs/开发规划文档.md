## 临床情景与系统目标

系统模拟 CPR 急救全过程的三个临床阶段：

| 阶段 | 瞳孔 | 颈动脉 | 眼灯/OLED | 电机 | `eyes_rgb_level` |
|------|------|--------|-----------|------|-----------------|
| **初始/未复苏** | 固定散大 | 无搏动 | 最低亮度/黑屏 | 静止 | 0 |
| **按压/吹气中** | 保持散大 | 被动搏动(=按压频率) | 保持不变 | 随按压振动 | 0 |
| **抢救成功(ROSC)** | 正常/缩小 | 自主搏动(~70bpm) | 全亮/白底黑圆 | 固定频率 | 1 |

## Phase 2: Mainboard 临床实时反馈显示

> **临床背景**: 施救者在按压过程中需实时看到**按压深度光条**（是否达标 50~60mm）、**频率数码管**（是否在 100~120 次/分）、**倒计时**。这是"操作→反馈→调整"的临床闭环。当前 Sensor 板数据已就绪，但 Mainboard 端尚未接收和显示。

- [ ] **T2.2** (P0) Mainboard 实时显示联动

  **当前缺口**:
  - `rtt_system_work.c` 5 个定时回调**全部为空**（1ms/10ms/50ms/500ms/1s）
  - Sensor 成绩/数据帧到达 Mainboard 后**未解析**
  - 数码管 `nixietube_task.c` 已有显示函数但**未被调用**
  - 光条 `lightbar_task.c` 的 `TM1638_Set_LEDBar()` 已实现但**未联动**

  **实施步骤**:

  1. **`rtt_system_work.c` 定时回调填充** (`cpr-display-main-board/applications/macSYS/Src/rtt_system_work.c`):
     ```
     Timing_1ms():   调用 LED_DrvScan() — LED 呼吸/闪烁扫描
     Timing_10ms():  触摸按键扫描节拍
     Timing_50ms():  保留
     Timing_500ms(): 心跳检测 — 检查 Record.last_sensor_heartbeat 超时
     Timing_1s():    倒计时递减 MySysCfg.params[current_mode].countdown--
                     倒计时为 0 时自动停止并触发成绩计算
     ```

  2. **Sensor 数据帧解析** (`mainboard_nrf24l01_message.c`):
     - 在 `nrf24l01_protocol_operation()` 中增加 Sensor 数据上报帧（`CMD_TYPE_POST=0x66`）处理
     - 解析 `RasterReport_t`（64 字节）字段到 `MySysCfg.params[]`

  3. **数码管实时显示** (`nixietube_task.c`):
     - 按压频率: `TM1629A_Display_PressFreq(freq)` — 已有函数
     - 倒计时: `TM1629A_Display_Countdown(remaining_sec)` — 已有函数
     - 在 Data_Transmit 线程或 Timing_50ms 中调用

  4. **光条深度联动** (`lightbar_task.c`):
     - 按压深度 → `TM1638_Set_LEDBar(depth_normalized)` — 已有函数
     - 在 Timing_10ms 或 NRF 数据到达时更新

  **验证**: TC-MAIN-PER-008~009 通过，数码管实时显示频率+倒计时，光条随深度变化

## Phase 4: 头部板开发（全新工程）⭐可并行

> **临床背景**: 瞳孔从"固定散大"变为"恢复正常"是评估复苏效果的**核心视觉信号**。头部板将这一临床状态转化为 RGB 眼灯 + OLED 屏幕的可视化反馈。当前头部板工程**完全不存在**，需从零创建。

- [ ] **T4.1** (P0) 头部板工程骨架

  **当前缺口**: `cpr-head-board/` 目录不存在，无 CubeMX 工程，无源码

  **实施步骤**:
  1. 创建 `cpr-head-board/` 工程目录结构
  2. CubeMX 配置（STM32F103C6T6, LQFP-48）:
     - TIM1_CH4 PWM + DMA1_CH4（PA11，WS2812B 数据）
     - GPIO 输入 PA2/PA3/PA4（上拉，瞳孔编码）
     - GPIO 输出 PC10/PC11（软 I2C，OLED）
     - USART1 PA9/PA10（调试，115200）
     - HSE 8MHz → SYSCLK 72MHz
  3. 裸机工程（无 RTOS），主循环结构
  4. 调试串口 printf 重定向

  **验证**: 工程编译通过，下载运行，USART1 输出初始化日志

- [ ] **T4.2** (P0) 瞳孔状态 GPIO 解码

  **当前缺口**: 无任何代码

  **实施步骤**:
  1. GPIO 初始化（PA2/PA3/PA4，上拉输入）
  2. 3 位编码读取: `state = (PA4<<2)|(PA3<<1)|PA2`
  3. 状态变化检测: 仅 state 改变时触发更新
  4. 编码映射: 0=濒死/散大, 1=正常/恢复, 2~7=预留

  **验证**: Sensor 切换 PC10/11/12 输出 → 头部板日志正确显示解码值

- [ ] **T4.3** (P0) WS2812B RGB 眼灯驱动

  **当前缺口**: 无代码

  **参考**: Sensor 板 `bsp_ws2812b.c` PWM+DMA 实现（663 行），大幅裁剪为单灯

  **实施步骤**:
  1. TIM1 CH4 PWM + DMA1_CH4 配置（800kHz WS2812B 时序）
  2. GRB 编码: 0 码=0.35us/0.8us, 1 码=0.7us/0.6us
  3. 亮度控制: 3%（濒死）/ 100%（正常），白光 (255,255,255)
  4. DMA 双缓冲传输（参考 Sensor `update_sequence()`）

  **验证**: 示波器确认 PA11 PWM 波形，状态 0/1 切换亮度正确

- [ ] **T4.4** (P0) OLED 眼屏驱动

  **当前缺口**: 无代码（原 Sensor 板 `bsp_oled_eye.c` 已删除，需在头部板重建）

  **实施步骤**:
  1. 软 I2C GPIO bit-bang（PC10=SCL, PC11=SDA）
  2. ST7315 初始化序列（64×48, I2C 地址 0x3C, 6 页）
  3. 帧缓冲区 + 图形原语:
     - `fb_clear()` — 全黑（濒死）
     - `fb_fill_white()` + `fb_draw_filled_circle(32,24,12)` — 白底黑圆（正常）
     - `fb_flush()` — 写入 OLED
  4. 状态 API: `oled_eye_dying()` / `oled_eye_normal()`

  **验证**: 肉眼确认两种状态显示正确，逻辑分析仪确认 I2C 波形

- [ ] **T4.5** (P1) 眼部状态联动主循环

  **当前缺口**: 无代码

  **实施步骤**:
  1. 主循环: 轮询瞳孔 GPIO → 解码 → 变化检测 → 联动 RGB + OLED
  2. 状态切换映射:

     | 瞳孔状态 | WS2812B | OLED |
     |----------|---------|------|
     | 0（濒死/散大） | 3% 白光 | 黑屏 |
     | 1（正常/恢复） | 100% 白光 | 白底黑圆 |

  3. 调试串口输出状态变化日志

  **验证**: Sensor 端切换 `eyes_rgb_level` → 头部板 RGB + OLED 同步切换

## Phase 5: 考核模式（操作流程检查 + 成绩单）

> **临床背景**: 考核模式需评估施救者是否按标准急救流程操作。10 项检查涵盖"判断意识→检查脉搏→呼救→清除异物→开放气道→按压/吹气→评估复苏"的完整链路。成绩单是最终临床能力评定。

- [ ] **T5.1** (P1) 10 项操作流程检查

  **当前缺口**:
  - `touch_task.c` 中 4 个回调**为空**: `TOUCH_CONSCIOUS_JUDGMENT` / `TOUCH_SPHYMOSCOPY` / `TOUCH_EMERGENCY_CALL` / `TOUCH_REMOVE_FOREIGN`
  - `start_task.c` 中 CC6201 状态检测**两个分支均为空**
  - 无 10 项检查结果变量

  **10 项检查项与数据来源**:

  | # | 检查项 | 临床动作 | 传感器 | 实现文件 |
  |---|--------|---------|--------|---------|
  | 1 | 意识判断 | 拍打肩部 | 振动传感器 ADC(PA0/PA1) | Sensor→NRF→Mainboard |
  | 2 | 脉搏检查 | 触诊颈动脉 | KEY1/KEY2(PC14/PC13) | Sensor→NRF→Mainboard |
  | 3 | 检查呼吸 | 观察胸廓 | 光栅板数据辅助 | Sensor 计算 |
  | 4 | 急救呼叫 | 口头呼叫 | TOUCH_EMERGENCY_CALL 按键 | Mainboard touch_task |
  | 5 | 清除异物 | 检查口腔 | CC6201 霍尔(PC1) | Sensor→NRF→Mainboard |
  | 6 | 开放气道 | 头部上仰 | MPU6050 pitch≥15° | Sensor→NRF→Mainboard |
  | 7 | 急救前脉搏 | 按压前触诊 | KEY1/KEY2 | Sensor→NRF→Mainboard |
  | 8 | 急救后脉搏 | 按压后触诊 | KEY1/KEY2 | Sensor→NRF→Mainboard |
  | 9 | 急救前瞳孔 | 观察瞳孔 | 头部板状态 | Mainboard 记录 |
  | 10 | 急救后瞳孔 | 观察瞳孔 | 头部板状态 | Mainboard 记录 |

  **实施步骤**:
  1. `bsp_typedef.h` 新增 10 项检查结果变量（`uint8_t check_list[10]`）
  2. `touch_task.c` 补齐 4 个回调: 置位检查标志 + LED 指示 + 语音提示
  3. `start_task.c` 补齐 CC6201 检测: `cc6201_state` 变化时置位检查项
  4. Sensor→NRF 上报震动/触诊/异物事件 → Mainboard 置位对应检查项
  5. 考核模式结束时汇总 10 项结果到成绩单

  **验证**: TC-MAIN-PER-007 + TC-MODE-004~006 通过

- [ ] **T5.2** (P1) 成绩存储与三种模式成绩单打印

  **当前缺口**:
  - `cpr_record.c` **完全为空**（4 个函数声明无实现）
  - `printer_task.c` 主循环**仅发 "Hello\n"**
  - 无成绩单格式化逻辑

  **实施步骤**:
  1. **`cpr_record.c` Flash 存储**:
     - `cpr_storage_init()`: FAL 分区初始化（DATA 分区 16KB @ sector 248）
     - `cpr_save_record()`: `cpr_record_t`（60+ 字段）写入 Flash，带 CRC 校验
     - `cpr_get_recent()`: 读取最近 N 条记录
     - `cpr_clear_all()`: 擦除数据分区

  2. **`printer_task.c` 三种成绩单格式**:
     - **训练模式**: 基础信息 + 参数设定 + 按压报告 + 吹气报告 + 循环统计 + 用时 + 结果
     - **考核模式**: 额外 + **操作流程检查 10 项** + 循环间间断时间
     - **竞赛模式**: 额外 + 循环间间断时间 + 排名
     - 调用 `rd_dm32_printer.c` 已有 ESC/POS 命令集

  3. **触发机制**: `TOUCH_PRINTER` 按键 → 读取 Flash 记录 → 格式化 → 发送打印机

  **验证**: TC-MAIN-PER-013~014 + TC-MODE-001~009 全通过

```
T4.1 → T4.2 → T4.3/T4.4 → T4.5 (头部板) ───────→ M3 里程碑
  ⚠️ 可与 T2.2 并行

T5.1 (流程检查) ──→ T5.2 (成绩单) ──→ T7.1 (竞赛)
  依赖: T2.2 完成后数据可显示

T6.1/T6.2/T6.3 (Remote) ── 可与 Phase 5 并行
T7.2 (RS485) / T7.3 (健壮性) ── 可与任何并行
```

| 优先级 | 任务 | 原因 |
|--------|------|------|
| **P0** | T2.2 Mainboard 显示 | 解锁 M2 里程碑，临床数据流闭环 |
| **P0** | T4.1~T4.5 头部板 | 解锁 M3 里程碑，核心临床视觉信号 |
| **P1** | T5.1 + T5.2 考核+成绩单 | 解锁 M4 里程碑，完整训练模式 |
| **P1** | T6.2 Remote 联动 | 操作终端完整性 |
| **P1** | T7.1 竞赛 / T7.2 RS485 | 高级功能 |
| **P2** | T6.1 / T6.3 / T7.3 | 锦上添花 |
