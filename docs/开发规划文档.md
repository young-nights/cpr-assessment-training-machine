## 二、开发路线规划

### 设计原则

1. **先通信后业务**: 先打通板间通信链路，再逐步实现业务逻辑
2. **先数据流后评分**: 先让原始数据流动起来，再实现评分算法
3. **先训练后考核/竞赛**: 训练模式最简单（无操作流程检查），作为第一个可运行目标
4. **可并行则并行**: 不同板的独立模块可同时开发
5. **遵循 AGENTS.md 约束**: 协议变更同步六处、文档与代码一致、as-built 为准

#### T0.1 统一 `eyes_rgb_level` 语义（红线任务）

**问题**: 眼灯状态字段四处语义不一致：
- docs v2.1: 0=濒死 / 1=正常
- mainboard `bsp_typedef.h:84`: 0=关闭 / 1=涣散 / 2=清醒
- 测试用例 TC-START-005: 期望 CPR 开始=0 濒死
- 运行现实: 上电恒白光

**行动项**:
1. 确定最终语义方案（推荐: 0=濒死 / 1=正常，与 docs 和测试用例一致）
2. 修改 mainboard `bsp_typedef.h` 注释
3. 确保 TC-START-005~007 期望值与代码一致
4. **注意**: Sensor 板 WS2812B 控制逻辑需同步适配头部板 GPIO 瞳孔通信协议（T1.3）
5. 同一提交内同步五板 + docs + 测试用例表

#### T0.2 明确两套帧定义的适用场景

**现状**: 代码并存两套帧定义，分别用于不同通信链路：
- **nRF24L01 无线帧**: `0x55 0xAA LEN ID_H ID_L TYPE STATE DATA CRC16`（message.c 组帧）— 无线主通信通道
- **RS485 有线帧**: `cpr_packet_t`（dev_type+seq 版，`mainboard_cpr_protocol.h`）— 有线备用通道

**行动项**:
1. 在 `mainboard_cpr_protocol.h` 头部注释明确标注"仅用于 RS485 有线通信链路"
2. 在 message.c 头部注释明确标注"仅用于 nRF24L01 无线通信链路"
3. 在 docs 中清晰区分两套帧的使用场景和适用链路
4. 确保开发者不会混用两套帧格式

### Phase 1: Sensor 板 — 通信基础（核心瓶颈）

> **目标**: Sensor 板具备 NRF24L01 通信 + UART2 光栅数据接收能力，与 Mainboard 建立连接
> **预计工时**: 5~8 天
> **并行关系**: T1.1 与 T1.2 可并行；T1.3 依赖 T1.1

#### T1.1 Sensor 板 NRF24L01 驱动与协议栈 ⭐最高优先级

**工作量**: 大（约 2000~3000 行代码）

**硬件接口**: SPI3（SCK=PB3, MISO=PB4, MOSI=PB5）+ CE=PB7, CSN=PB6, IRQ=PD2

**参考模板**: Mainboard 的 `macNRF/` 三件套（driver.c 659行 + spi.c 164行 + message.c 613行）。三板 NRF 驱动结构高度一致，可复制后适配。

**交付件**:
1. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_spi.c/h`
   - SPI3 设备初始化（1MHz, MODE_0）
   - IRQ GPIO 配置（PD2, 下降沿中断）
   - CE=PB7 / CSN=PB6 引脚控制
   - 底层 SPI 读写封装
2. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_driver.c/h`
   - NRF24L01 寄存器级驱动（参数配置、SPI 回环检测、FIFO 管理、PTX/PRX 切换）
3. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_message.c/h`
   - CRC16-Modbus 校验
   - 帧构建器（0x55AA 格式，DEVICE_ID=0x0005）
   - 7 步状态机帧解析器
   - 命令分发：连接应答、开始指令确认、WS2812B/电机/CC6201 应答
4. `cpr-sensor-device/applications/macTask/sensor_nrf24l01_task.c`
   - NRF 接收线程（IRQ 信号量等待 → 读 FIFO → 协议解析）
   - 解码线程（连接 ACK 回复、事件驱动）
   - 数据发送线程（Sensor→Mainboard 数据上报）
5. CubeMX SPI3 + GPIO(PB3/PB4/PB5/PB7/PB6/PD2) 配置

**验证标准**:
- TC-SENSOR-INIT-001~005 全通过
- TC-SENSOR-CONN-001~003 全通过
- Sensor 与 Mainboard 握手成功，`nrf_if_connected = 1`

#### T1.2 Sensor 板 UART2 光栅板通信协议 ⭐高优先级

**工作量**: 中等（约 500~800 行代码）

**硬件接口**: USART2（TX=PA2, RX=PA3, 115200bps）

**交付件**:
1. CubeMX UART2 配置（115200bps, 中断接收）
2. `cpr-sensor-device/applications/macBSP/Src/uart2_protocol.c/h`
   - 循环队列（64 字节）+ 互斥锁保护
   - UART2 中断接收回调（写入循环队列）
   - 5 状态帧解析状态机（帧头→长度→数据→校验→帧尾）
   - `process_realtime_frame()`: 脉冲增量累加、深度计算
   - 超时保护（50ms 解析超时重置）
3. `cpr-sensor-device/applications/macTask/uart2_task.c`
   - UART2 数据处理线程

**验证标准**:
- TC-PRESS-004~008 全通过
- TC-BLOW-004~005 全通过

#### T1.3 Sensor 板开始序列与基础业务循环

**工作量**: 中等

**依赖**: T1.1（NRF 通信）

**交付件**:
1. 完善 `bsp_typedef.c` 中 `system_param_init()`
2. 创建 `nrf24l01_events` 事件集
3. 开始指令处理：`FRAME_NRF24_SEND_TO_SENSOR_START_CMD` → 置位标志 → 回复 ACK
4. WS2812B/电机状态设置命令的接收与响应
5. CC6201 霍尔传感器 GPIO(PC1) 中断检测 + NRF 上报
6. 振动传感器检测 + 震动反馈 NRF 上报
   - ADC 模拟量: PA0（传感器1）, PA1（传感器2）
   - DOUT 数字量: PB9（传感器1）, PB8（传感器2）
7. **瞳孔通信 GPIO 输出**（新增）:
   - PC10/PC11/PC12 GPIO 输出 → 头部板 PA2/PA3/PA4
   - 定义瞳孔状态编码协议（3 位编码，0=濒死/1=正常）
   - 收到 Mainboard 眼灯指令时，同时输出瞳孔状态编码

**验证标准**:
- TC-START-003、TC-START-006、TC-START-009 全通过
- TC-SENSOR-PER-007~011 全通过
- Sensor 与 Mainboard 完成完整开始序列（step0→step1→step2→step3）
- 头部板正确接收瞳孔状态信号

### Phase 2: 数据通路打通 — 按压/吹气数据流

> **目标**: 从光栅板脉冲到 Mainboard 数码管显示的完整数据通路
> **预计工时**: 3~5 天
> **并行关系**: T2.1 依赖 Phase 1；T2.2 与 T2.1 部分并行

#### T2.1 Sensor 板成绩计算模块

**工作量**: 大（约 800~1200 行代码）

**交付件**:
1. `cpr-sensor-device/applications/macSYS/Src/cpr_calculator.c/h`
   - `Calculator_Init()`: 清零所有状态和记录
   - 按压事件检测：方向变化(0→1=下压开始, 1→-1→0=按压结束)
   - 按压参数计算：深度达标(500~600, 0.1mm)、频率(60000/interval_ms)
   - 吹气事件检测：方向变化(0→1=充气开始, 1→-1→0=吹气结束)
   - 吹气参数计算：潮气量达标(500~600, 0.1mm)、吹气时间
   - 循环计数：30 按压 + 2 吹气 = 1 循环
   - `Calculator_Finalize()`: 汇总 RasterReport_t（64 字节）
   - 结果判定：至少 1 个完整循环且按压正确率 ≥ 70% → 成功
2. Sensor→Mainboard 成绩上报通过 NRF 帧（`CMD_TYPE_POST=0x66`）

**验证标准**:
- TC-CALC-001~019 全通过

#### T2.2 Mainboard 定时回调与显示联动

**工作量**: 中等

**交付件**:
1. `rtt_system_work.c` 定时回调填充:
   - `Timing_1ms()`: LED 扫描（`LED_DrvScan()`）
   - `Timing_10ms()`: 触摸按键扫描节拍
   - `Timing_50ms()`: 保留
   - `Timing_500ms()`: 心跳检测（Sensor/Remote 最后通信时间）
   - `Timing_1s()`: 倒计时递减（`MySysCfg.params[current_mode].countdown--`）
2. 成绩数据接收处理：NRF 消息处理中增加 Sensor 成绩帧解析
3. 数码管实时显示：按压频率、倒计时（`nixietube_task.c`）
4. 光条联动：按压深度（`lightbar_task.c` 的 `TM1638_Set_LEDBar()`）

**验证标准**:
- TC-MAIN-PER-008~009 通过
- 数码管实时显示按压频率和倒计时

> **预计工时**: 3~5 天
> **并行关系**: 可与 Phase 2 / Phase 3 并行开发（硬件独立）
> **依赖**: 仅需瞳孔状态编码协议定义（T1.3 中定义）

#### T4.1 头部板工程骨架

**工作量**: 小

**交付件**:
1. 创建 `cpr-head-board/` 工程目录
2. CubeMX 配置（STM32F103C6T6, LQFP-48）

#### T4.2 瞳孔状态 GPIO 输入与解码

**工作量**: 小~中

**硬件接口**: PA2/PA3/PA4（GPIO 输入，上拉），来自 Sensor 板 PC10/PC11/PC12

**交付件**:
1. GPIO 中断或轮询读取 3 路信号
2. 瞳孔状态解码逻辑（根据 T1.3 定义的编码协议）
3. 状态变化检测（避免重复处理）

#### T4.3 WS2812B RGB 眼灯驱动

**工作量**: 中等

**硬件接口**: PA11（TIM1_CH4 PWM + DMA）

**参考**: Sensor 板 `bsp_ws2812b.c` PWM+DMA 实现（870 行），可大幅裁剪复用

**交付件**:
1. TIM1 CH4 PWM + DMA1 配置
2. WS2812B 单灯驱动（GRB 编码、PWM 波形）
3. 状态映射:
   - 濒死 = 最低亮度白光（~3% 占空比）
   - 正常 = 全亮白光（100% 占空比）

#### T4.4 OLED 眼屏驱动

**工作量**: 中等

**硬件接口**: PC10(SCL) / PC11(SDA) — 软 I2C

**交付件**:
1. 位脉冲 I2C 驱动（GPIO bit-bang）
2. ST7315 初始化（64×48, I2C 地址 0x3C, 6 页）
3. 图形绘制:
   - 濒死 = 黑屏（全灭）
   - 正常 = 白底中间黑圆

#### T4.5 头部板业务主循环

**工作量**: 小

**交付件**:
1. 主循环: 轮询瞳孔 GPIO → 解码状态 → 联动控制 RGB + OLED
2. 调试串口输出（USART1, 115200bps）

**验证标准**:
- Sensor 输出不同瞳孔编码 → RGB 亮度/OLED 显示正确切换
- TC-SENSOR-PER-001~003（眼灯/眼屏部分）在头部板上验证

#### T5.2 Mainboard 成绩存储与打印机业务

**验证标准**:

## 六、已知风险与注意事项

### 6.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Sensor 板 .ioc 外设零配置 | NRF/MPU/ADC128S 引脚未分配 | 必须走 CubeMX 重新配置，禁止直接按 docs 引脚接线 |
| 两套帧定义并存 | 新开发者容易混用 | Phase 0 清理废弃定义 |
| eyes_rgb_level 四处矛盾 | 眼灯状态可能错误 | Phase 0 优先统一 |
| WT588D_Stop() bug | 停止命令不生效 | Phase 0 修正命令码 |
| 头部板全新工程 | 零基础，需搭建完整工程 | 参考其他板 CubeMX 配置模式 |
| 瞳孔编码协议未定义 | Sensor 与头部板无法对接 | T1.3 中先定义协议，T4.2 适配 |

### 6.2 AGENTS.md 约束提醒

1. **协议变更同步六处**: mainboard + sensor + remote + raster + docs + 测试用例表，同一提交
2. **as-built 为准**: 与设计文档冲突时以代码实际行为为准
3. **禁止单方面修改 `eyes_rgb_level` 语义**
4. **源码注释英文 + Doxygen**
5. **`embedded_lib/` 只读**
6. **涉及多板协议的改动必须同一提交内联动**

### 6.3 测试用例覆盖

- 头部板上电初始化
