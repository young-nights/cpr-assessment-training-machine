## 二、开发路线规划

### 设计原则

1. **先通信后业务**: 先打通四板间通信链路，再逐步实现各板业务逻辑
2. **先数据流后评分**: 先让原始数据流动起来，再实现评分算法
3. **先训练后考核/竞赛**: 训练模式最简单（无操作流程检查），作为第一个可运行目标
4. **可并行则并行**: 不同板的独立模块可同时开发
5. **遵循 AGENTS.md 约束**: 协议变更同步六处、文档与代码一致、as-built 为准

### Phase 1: Sensor 板 — 通信基础（核心瓶颈）

> **目标**: Sensor 板具备 NRF24L01 通信能力 + UART2 光栅数据接收能力，与 Mainboard 建立连接
> **预计工时**: 5~8 天
> **并行关系**: T1.1 与 T1.2 可并行；T1.3 依赖 T1.1

#### T1.1 Sensor 板 NRF24L01 驱动与协议栈 ⭐最高优先级

**工作量**: 大（约 2000~3000 行代码）

**参考模板**: Mainboard 的 `macNRF/` 三件套（driver.c 659行 + spi.c 164行 + message.c 613行），以及 Remote 的对应实现。三板的 NRF24L01 驱动结构高度一致，可复制后适配。

**交付件**:
1. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_spi.c/h`
   - SPI1 设备初始化（1MHz, MODE_0）
   - IRQ GPIO 配置（PD2, 下降沿中断）
   - CE/CSN 引脚控制
   - 底层 SPI 读写封装
2. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_driver.c/h`
   - NRF24L01 寄存器级驱动（参数配置、SPI 回环检测、FIFO 管理、PTX/PRX 切换等）
3. `cpr-sensor-device/applications/macNRF/Src/sensor_nrf24l01_message.c/h`
   - CRC16-Modbus 校验
   - 帧构建器（0x55AA 格式，DEVICE_ID=0x0005）
   - 7 步状态机帧解析器
   - 命令分发：连接应答、开始指令确认、WS2812B/电机/CC6201 应答
4. `cpr-sensor-device/applications/macTask/sensor_nrf24l01_task.c`
   - NRF 接收线程（IRQ 信号量等待 → 读 FIFO → 协议解析）
   - 解码线程（连接 ACK 回复、事件驱动）
   - 数据发送线程（Sensor→Mainboard 数据上报）
5. CubeMX SPI1 + GPIO(PD2) 重新配置（sensor 板 .ioc 中 NRF24L01 零配置）

**验证标准**:
- TC-SENSOR-INIT-001~005 全通过
- TC-SENSOR-CONN-001~003 全通过
- Sensor 与 Mainboard 握手成功，`nrf_if_connected = 1`

#### T1.2 Sensor 板 UART2 光栅板通信协议 ⭐高优先级

**工作量**: 中等（约 500~800 行代码）

**交付件**:
1. CubeMX UART2 配置（115200bps, PA2=TX, PA3=RX, 中断接收）
2. `cpr-sensor-device/applications/macBSP/Src/uart2_protocol.c/h`
   - 循环队列（64 字节）+ 互斥锁保护
   - UART2 中断接收回调（写入循环队列）
   - 5 状态帧解析状态机（等待帧头→读长度→读数据→校验→检查帧尾）
   - `process_realtime_frame()`: 处理 8 字节实时帧（脉冲增量累加、深度计算）
   - 超时保护（50ms 解析超时重置）
3. `cpr-sensor-device/applications/macTask/uart2_task.c`
   - UART2 数据处理线程（从循环队列读取 → 帧解析 → 数据累加）
   - 或将解析逻辑放入 `Timing_10ms()` / `Timing_50ms()` 回调

**验证标准**:
- TC-PRESS-004~008 全通过
- TC-BLOW-004~005 全通过
- 光栅板发送脉冲帧 → Sensor 正确累加并计算深度

#### T1.3 Sensor 板开始序列与基础业务循环

**工作量**: 中等

**依赖**: T1.1（NRF 通信）

**交付件**:
1. 完善 `bsp_typedef.c` 中 `system_param_init()`
2. 创建 `nrf24l01_events` 事件集
3. 实现开始指令处理：收到 `FRAME_NRF24_SEND_TO_SENSOR_START_CMD` → 置位标志 → 回复 ACK
4. 实现 WS2812B/电机状态设置命令的接收与响应
5. 实现 CC6201 霍尔传感器 GPIO 中断检测 + NRF 上报
6. 实现压电陶瓷片 ADC 检测 + 震动反馈 NRF 上报

**验证标准**:
- TC-START-003、TC-START-006、TC-START-009 全通过
- TC-SENSOR-PER-007~011 全通过
- Sensor 与 Mainboard 完成完整开始序列（step0→step1→step2→step3）

### Phase 2: 数据通路打通 — 按压/吹气数据流

> **目标**: 从光栅板脉冲到 Mainboard 数码管显示的完整数据通路
> **预计工时**: 3~5 天
> **并行关系**: T2.1 依赖 Phase 1；T2.2 与 T2.1 部分并行

#### T2.1 Sensor 板成绩计算模块

**工作量**: 大（约 800~1200 行代码）

**交付件**:
1. `cpr-sensor-device/applications/macSYS/Src/cpr_calculator.c/h`
   - `Calculator_Init()`: 清零所有状态和记录
   - 按压事件检测：方向变化(0→1=下压开始, 1→-1→0=按压结束)
   - 按压参数计算：深度达标判定(500~600, 0.1mm)、频率计算(60000/interval_ms)
   - 吹气事件检测：方向变化(0→1=充气开始, 1→-1→0=吹气结束)
   - 吹气参数计算：潮气量达标判定(500~600, 0.1mm)、吹气时间
   - 循环计数：30 按压 + 2 吹气 = 1 循环
   - `Calculator_Finalize()`: 汇总 RasterReport_t 结构体（64 字节）
   - 结果判定：至少 1 个完整循环且按压正确率 ≥ 70% → 成功
2. Sensor→Mainboard 成绩上报通过 NRF 帧（`CMD_TYPE_POST=0x66`）

**验证标准**:
- TC-CALC-001~019 全通过
- 使用模拟脉冲数据验证全部计算逻辑

#### T2.2 Mainboard 定时回调与显示联动

**工作量**: 中等

**交付件**:
1. `rtt_system_work.c` 定时回调填充:
   - `Timing_1ms()`: LED 扫描（`LED_DrvScan()`）
   - `Timing_10ms()`: 触摸按键扫描节拍
   - `Timing_50ms()`: 保留
   - `Timing_500ms()`: 心跳检测（检查 Sensor/Remote 最后通信时间）
   - `Timing_1s()`: 倒计时递减逻辑（`MySysCfg.params[current_mode].countdown--`）
2. 成绩数据接收处理：Mainboard NRF 消息处理中增加 Sensor 成绩帧解析
3. 数码管实时显示联动：按压频率、倒计时等通过 `nixietube_task.c` 已有函数更新
4. 光条联动：按压深度通过 `lightbar_task.c` 的 `TM1638_Set_LEDBar()` 更新

**验证标准**:
- 数码管实时显示按压频率和倒计时
- 光条随按压深度变化
- TC-MAIN-PER-008~009 通过
