## 临床情景总览

系统完整模拟一次 CPR 急救全过程，分为三个临床阶段：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        CPR 急救临床路径                               │
│                                                                     │
│  ① 初始/未复苏          ② 按压/吹气中         ③ 抢救成功(ROSC)      │
│  ─────────────          ─────────────         ─────────────────     │
│  瞳孔：固定散大          瞳孔：保持散大          瞳孔：恢复正常       │
│  颈动脉：无搏动          颈动脉：被动搏动         颈动脉：自主搏动     │
│  眼灯：最低亮度          眼灯：保持最低           眼灯：全亮白光       │
│  OLED：黑屏              OLED：保持黑屏          OLED：白底黑圆       │
│  电机：静止              电机：随按压振动         电机：固定频率自激   │
│  ─────────────          ─────────────         ─────────────────     │
│  临床意义：              临床意义：               临床意义：           │
│  心跳骤停，脑缺氧        人工循环建立，           复苏有效，           │
│  导致固定散大瞳孔        脑功能尚未恢复           脑灌注改善           │
└─────────────────────────────────────────────────────────────────────┘
```

**施救者操作流程**（考核模式检查的 10 项步骤）：

```
判断意识(肩部拍打) → 检查脉搏(颈动脉触诊) → 检查呼吸 → 急救呼叫
    → 清除异物 → 开放气道(头部上仰) → 胸外按压(30次) → 人工呼吸(2次)
    → 重复 5 个循环 → 评估结果(瞳孔/脉搏/呼吸)
```

## Phase 1: Sensor 通信链路（核心瓶颈）

> **临床背景**: Sensor 板是假人传感器中枢——施救者的每一个操作（按压、吹气、拍肩、触诊）都由 Sensor 板采集，再通过无线链路传给 Mainboard 实时反馈。通信不通，一切临床数据都无法流动。

- [X] **T1.1** (P0) NRF24L01 无线通信链路 ⭐最高优先级

  - 临床意义: Sensor 板与 Mainboard 的"神经系统"——按压数据、眼灯指令、电机控制、异物状态全靠此链路
  - 硬件: SPI3（SCK=PB3, MISO=PB4, MOSI=PB5）+ CE=PB7, CSN=PB6, IRQ=PD2
  - 交付: `macNRF/` 三件套（driver 667行 + spi 168行 + message 436行）+ `sensor_nrf24l01_task.c`（3 线程）
  - 判定: TC-SENSOR-INIT-001~005 + TC-SENSOR-CONN-001~003 通过

- [X] **T1.2** (P0) UART2 光栅板数据接收 ⭐高优先级

  - 临床意义: 光栅编码器检测施救者按压深度/吹气量——这是 CPR 质量的核心数据源
  - 硬件: USART2（TX=PA2, RX=PA3 ↔ 光栅 RX=PD6, TX=PD5）
  - 交付: `uart2_protocol.c`（515行）：帧解析、脉冲累加、深度计算、模式切换指令
  - 判定: TC-PRESS-004~008 + TC-BLOW-004~005 通过

- [X] **T1.3** (P0) 开始序列与传感器初始化

  - 临床意义: 施救者按"开始"→ 模拟人进入**濒死状态**（瞳孔散大+无搏动），开始前置检查流程
  - 交付: NRF 开始指令处理 + CC6201 异物检测 + 振动传感器（意识判断）+ 瞳孔 GPIO 输出 + 电机初始化
  - 判定: TC-START-003/006/009 + TC-SENSOR-PER-007~011 通过

## Phase 2: 临床数据通路（按压/吹气）

> **临床背景**: 施救者执行胸外按压和人工呼吸时，系统需实时计算每次按压的**深度、频率、回弹**和每次吹气的**潮气量、时间**，评估是否符合 AHA/ERC 国际指南标准（按压深度 50~60mm，频率 100~120 次/分，潮气量 500~600ml）。

- [X] **T2.1** (P0) CPR 成绩计算模块

  - 临床意义: 将原始脉冲数据转化为**临床质量指标**——每一次按压/吹气是否达标
  - 计算逻辑（符合 AHA 2020 指南）:
    - 按压: 深度达标(50~60mm)、频率(100~120次/分)、回弹完整、位置正确
    - 吹气: 潮气量(500~600ml)、吹气时间、进胃误判
    - 循环: 30 次按压 + 2 次吹气 = 1 循环，共 5 循环
    - 结果: ≥1 完整循环且按压正确率 ≥70% → 复苏成功
  - 交付: `app_calculator.c`（444行）：事件检测、参数计算、RasterReport_t(64B) 组装
  - 判定: TC-CALC-001~019 全通过

- [ ] **T2.2** (P1) Mainboard 临床实时反馈显示

  - 临床意义: 施救者在操作过程中**实时看到**按压深度光条、频率数码管、倒计时——形成"操作→反馈→调整"闭环
  - 交付:
    - `rtt_system_work.c` 定时回调: LED 扫描 + 触摸节拍 + 心跳 + 倒计时
    - 数码管: 按压频率实时显示（nixietube_task.c）
    - 光条: 按压深度渐变（TM1638 lightbar_task.c）
  - 判定: TC-MAIN-PER-008~009 通过

## Phase 3: 传感器完善（姿态/压力/电机）

> **临床背景**: 除按压/吹气数据外，系统还需检测：施救者是否正确**开放气道**（头部上仰）、按压**位置**是否正确、是否正确执行**意识判断**（拍肩）和**脉搏检查**（触诊颈动脉）。

- [X] **T3.1** (P0) MPU6050 头部姿态检测

  - 临床意义: 检测施救者是否正确**开放气道**——吹气前头部需上仰 ≥15°（仰头抬颏法）
  - 交付: `macMPU/` 三件套（驱动+校准+欧拉角，~565行）：pitch ≥15° 且速率 ≥30°/s 且持续 ≥100ms
  - 判定: TC-BLOW-001~003 通过

- [X] **T3.2** (P0) ADC128S102 按压点位检测

  - 临床意义: 检测施救者按压**位置**是否正确（胸骨下半段），5 个方位 + 气道开启 + 吹气进胃指示
  - 交付: `adc128s102cimtx.c`（188行）：SPI1 8 通道 ADC + 阈值判断
  - 判定: TC-PRESS-001~003 通过

- [X] **T3.3** (P1) 三路信号联合判别（按压 vs 吹气）

  - 临床意义: 区分施救者当前动作是**胸外按压**还是**人工呼吸**，以便光栅板正确计量
  - 判别逻辑: 有压力→按压；无压力+头部上仰→吹气；冲突→按压优先
  - 交付: 集成在 `uart2_protocol.c` 中（`detect_state_et` + 模式切换指令 CMD=0x11）
  - 判定: TC-JOINT-001~005 通过

- [X] **T3.4** (P1) 颈动脉脉搏模拟（空心杯电机）

  - 临床意义: 模拟颈动脉搏动的三种临床状态：
    - **无搏动**（心跳骤停）→ 电机静止
    - **被动搏动**（按压中，人工循环）→ 电机随按压频率振动
    - **自主搏动**（ROSC，自主循环恢复）→ 电机固定 ~70bpm 自激
  - 附加: KEY1/KEY2 触诊按键触发 500ms 振动（脉搏检查模拟）
  - 交付: `rtt_system_work.c` Timing_10ms() 三态状态机
  - 判定: TC-SENSOR-PER-004~006 通过

## Phase 4: 头部板（眼部临床显示）⭐可并行

> **临床背景**: 眼部是评估复苏效果的**核心视觉窗口**——瞳孔从"固定散大"变为"恢复正常"是"复苏有效、脑灌注改善"的关键信号。头部板负责将这一临床状态转化为 RGB 眼灯 + OLED 屏幕的可视化反馈。

- [ ] **T4.1** (P0) 头部板工程骨架

  - 交付: `cpr-head-board/` 目录 + CubeMX 配置（STM32F103C6T6, TIM1_CH4 PWM+DMA, GPIO 输入, 软 I2C, USART1）
  - 判定: 工程可编译下载，调试串口正常

- [ ] **T4.2** (P0) 瞳孔状态 GPIO 解码

  - 临床意义: 解码 Sensor 板传来的瞳孔状态编码（3 位 GPIO）
  - 编码: 0=濒死/散大, 1=正常/恢复, 2~7 预留
  - 交付: PA2/PA3/PA4 GPIO 输入 + 状态解码 + 变化检测
  - 判定: 切换 Sensor 编码 → 头部板正确解码

- [ ] **T4.3** (P0) WS2812B RGB 眼灯驱动

  - 临床意义: **濒死**=微弱白光（瞳孔散大）→ **正常**=全亮白光（瞳孔恢复）
  - 交付: PA11 TIM1_CH4 PWM+DMA，GRB 编码，3%/100% 亮度
  - 判定: 示波器确认 PWM 波形，状态切换亮度正确

- [ ] **T4.4** (P0) OLED 眼屏驱动

  - 临床意义: **濒死**=黑屏（对光反射消失）→ **正常**=白底黑圆（瞳孔恢复正常形态）
  - 交付: PC10/PC11 软 I2C + ST7315(64×48) + 图形绘制
  - 判定: 逻辑分析仪确认 I2C + 肉眼确认显示

- [ ] **T4.5** (P1) 眼部状态联动主循环

  - 临床意义: Sensor 切换瞳孔状态 → RGB + OLED **同步**切换，形成完整眼部临床反馈
  - 交付: 主循环（轮询 GPIO→解码→联动）+ 调试串口输出
  - 判定: TC-SENSOR-PER-001~003 在头部板验证

## Phase 5: 考核模式（操作流程检查 + 成绩单）

> **临床背景**: 考核模式需评估施救者是否按标准流程执行 CPR——10 项操作流程检查涵盖从"判断意识"到"评估复苏"的完整急救链。成绩单是最终的临床能力评定。

- [ ] **T5.1** (P1) 10 项操作流程检查

  - 临床意义: 考核施救者的**急救流程规范性**：
    1. 意识判断（拍肩）→ 2. 脉搏检查（触诊颈动脉）→ 3. 检查呼吸 → 4. 急救呼叫
    → 5. 清除异物 → 6. 开放气道（头部上仰）→ 7. 急救前脉搏 → 8. 急救后脉搏
    → 9. 急救前瞳孔 → 10. 急救后瞳孔
  - 交付: Mainboard `touch_task.c` 4 个空回调补齐 + `start_task.c` CC6201 检测 + 10 项检查变量
  - 判定: TC-MAIN-PER-007 + TC-MODE-004~006 通过

- [ ] **T5.2** (P1) 成绩存储与三种模式成绩单打印

  - 临床意义: 成绩单记录**完整的 CPR 质量报告**——供教官评估施救者临床能力
  - 三种模式差异:
    - **训练**: 自由练习，基础统计（无流程检查，不强制评分）
    - **考核**: 标准达标率评分 + 10 项流程检查 + 循环间间断时间
    - **竞赛**: 限时竞技 + 循环间间断时间 + 排名
  - 交付: `cpr_record.c` Flash 存储 + `printer_task.c` 三种格式成绩单
  - 判定: TC-MAIN-PER-013~014 + TC-MODE-001~009 全通过

## 临床数据流全景

```
施救者操作           传感器检测            数据处理              反馈显示
───────────         ──────────           ──────────           ──────────
胸外按压     ──→  光栅编码器(A/B相)  ──→  Sensor 深度计算  ──→  Mainboard 光条
按压位置     ──→  ADC128S(5方位)    ──→  位置判定        ──→  Mainboard LED
按压频率     ──→  光栅脉冲间隔      ──→  频率=60000/ms   ──→  Mainboard 数码管
人工呼吸     ──→  光栅(吹气方向)    ──→  潮气量计算      ──→  Remote 进度条
开放气道     ──→  MPU6050(pitch)   ──→  上仰判定≥15°   ──→  考核检查项
意识判断     ──→  振动传感器(ADC)   ──→  拍肩检测        ──→  考核检查项
脉搏触诊     ──→  KEY1/KEY2        ──→  触发电机振动    ──→  颈动脉反馈
异物检查     ──→  CC6201(霍尔)     ──→  异物状态        ──→  考核检查项
瞳孔状态     ──→  (Mainboard 判定) ──→  瞳孔 GPIO 编码  ──→  头部板 RGB+OLED
复苏结果     ──→  成绩计算(5循环)   ──→  RasterReport    ──→  成绩单打印
```
