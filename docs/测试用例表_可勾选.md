## 1. NRF24L01 无线通信协议

### 1.1 帧格式与 CRC 校验

- [ ] **TC-NRF-001** 帧头校验  
  操作步骤: 构造一帧正确的 nRF24L01 数据包（HEAD=0x55 0xAA），通过 SPI 发送给接收端  
  预期现象: 接收端成功解析帧头，进入 Decode_Step_1 状态  
  验证方式: 检查接收端串口日志输出 "Parse SUCCESS" 或无 "0x55 fails" 错误

- [ ] **TC-NRF-002** CRC16-Modbus 校验正确  
  操作步骤: 构造帧 `55 AA 04 00 05 31 01 01 [正确CRC_H] [正确CRC_L]`，发送给接收端  
  预期现象: CRC 校验通过，调用 `nrf24l01_protocol_operation()`  
  验证方式: 接收端日志输出 "CRC Check" 相关成功信息，无 CRC FAILED 警告

- [ ] **TC-NRF-003** CRC 校验失败丢弃  
  操作步骤: 构造帧 `55 AA 04 00 05 31 01 01 [错误CRC]`，发送给接收端  
  预期现象: 帧被丢弃，不触发任何业务处理  
  验证方式: 接收端日志输出 "CRC Check FAILED" 警告

- [ ] **TC-NRF-004** 帧头错误恢复  
  操作步骤: 先发送 `AA AA ...`（错误帧头），再发送正确帧 `55 AA ...`  
  预期现象: 错误帧被丢弃，正确帧正常解析  
  验证方式: 日志显示一次解析失败后恢复正常

- [ ] **TC-NRF-005** 连续解析失败超时重置  
  操作步骤: 连续发送 10 帧以上格式错误的数据包  
  预期现象: Sensor 端 `consecutive_parse_fails` 达到 10 后自动重置 `Decode_Step = Decode_Step_0`  
  验证方式: 日志输出 "10 consecutive ... fails (timeout), resetting"

### 1.2 Pipe 区分与来源识别

- [ ] **TC-NRF-006** Mainboard Pipe1 识别 Sensor  
  操作步骤: Sensor 板通过 Pipe1 发送 ASK_CONNECT 帧  
  预期现象: Mainboard 解析时 `src = SRC_FROM_SENSOR`（从 DEVICE_ID=0x0005 识别）  
  验证方式: Mainboard 日志输出 "Receive from Sensor"

- [ ] **TC-NRF-007** Mainboard Pipe2 识别 Remote  
  操作步骤: Remote 板通过 Pipe2 发送 ASK_CONNECT 帧  
  预期现象: Mainboard 解析时 `src = SRC_FROM_REMOTE`（从 DEVICE_ID=0x0004 识别）  
  验证方式: Mainboard 日志输出 "Receive from Remote"

- [ ] **TC-NRF-008** Sensor 端拒绝非 Mainboard 来源  
  操作步骤: 模拟非 Mainboard 设备向 Sensor 发送数据  
  预期现象: Sensor 端日志输出 "Sensor received data not from Main!" 并拒绝处理  
  验证方式: 检查 `nrf24l01_protocol_operation()` 对 `src != SRC_FROM_MAIN` 的过滤

### 1.3 发送重试机制

- [ ] **TC-NRF-009** `nrf24l01_send_with_retry()` 发送成功  
  操作步骤: 正常通信环境下调用 `nrf24l01_send_with_retry(order, pipe, 3)`  
  预期现象: 首次发送即成功（TX_DS 置位），返回 `RT_EOK`，不再重试  
  验证方式: 日志输出 "TX OK (TX_DS set)"，无 "TX failed" 错误

- [ ] **TC-NRF-010** 发送失败后自动重试  
  操作步骤: 断开接收端电源，调用 `nrf24l01_send_with_retry(order, pipe, 3)`  
  预期现象: 重试 3 次后返回 `-RT_ETIMEOUT`  
  验证方式: 日志输出 3 次 "TX order ... retry N"，最终输出 "TX failed after 3 retries"

- [ ] **TC-NRF-011** MAX_RT 溢出处理  
  操作步骤: 持续发送到不存在的地址，触发 MAX_RT  
  预期现象: 检测到 MAX_RT 后跳出轮询，清除中断标志  
  验证方式: 日志输出 "TX failed: MAX_RT"

- [ ] **TC-NRF-012** PLOS 过高切换频道  
  操作步骤: 模拟高干扰环境，丢包计数超过 0x0A  
  预期现象: 检测到 PLOS 超限后 Flush TX FIFO  
  验证方式: 检查代码中 OBSERVE_TX 寄存器的 PLOS 判断逻辑

## 2. Sensor 板 — 上电初始化与连接

  操作步骤: Sensor 板上电  
  预期现象: `nRF24L01_Check_SPI_Community()` 返回成功  
  验证方式: 日志输出 "nRF24L01 check spi hardware successful"

- [ ] **TC-SENSOR-INIT-002** nRF24L01 参数配置  
  操作步骤: Sensor 板上电  
  预期现象: `nRF24L01_Param_Config()` 返回成功  
  验证方式: 日志输出 "nrf24 parameter config successfully"

- [ ] **TC-SENSOR-INIT-003** nRF24L01 中断引脚配置  
  操作步骤: Sensor 板上电  
  预期现象: IRQ 引脚 PD2 正确配置，信号量创建成功  
  验证方式: 日志输出 "nrf24 irq config successfully"，`nrf24_flags.using_irq == RT_TRUE`

- [ ] **TC-SENSOR-INIT-004** nRF24L01 FIFO 清空  
  操作步骤: Sensor 板上电  
  预期现象: 初始化完成后 RX/TX FIFO 均被清空  
  验证方式: 日志无 FIFO 相关错误

- [ ] **TC-SENSOR-INIT-005** UART2 光栅板通信初始化  
  操作步骤: Sensor 板上电

  验证方式: 日志输出 "Usart2 Device node created succeed!"

### 2.2 Sensor 连接建立

- [ ] **TC-SENSOR-CONN-001** Sensor 未连接时持续发送连接请求  
  操作步骤: Sensor 板上电（Mainboard 未上电或不在范围内）  
  预期现象: Sensor 每 500ms 通过 Pipe1 发送 ASK_CONNECT 帧，无上限重试  
  验证方式: 日志周期性输出 "Sensor → Mainboard: Send connect request... (retry N)"

- [ ] **TC-SENSOR-CONN-002** Sensor 发送连接请求后切换 PRX 等待 ACK  
  操作步骤: Sensor 发送 ASK_CONNECT 后  
  预期现象: CE 拉低 → 切换 PRX → CE 拉高，打开 200ms 接收窗口  
  验证方式: 日志显示 PTX 发送后切回 PRX 等待信号量

- [ ] **TC-SENSOR-CONN-003** Sensor 收到 ACK_CONNECT 后建立连接  
  操作步骤: Mainboard 回复 ACK_CONNECT 帧  
  预期现象: `Record.nrf_if_connected` 置为 1，停止发送连接请求  
  验证方式: 日志输出 "Set: 接收到从主板发来的连接指令的响应"，停止出现 retry 日志

## 4. 开始序列状态机

### 4.1 TOUCH_START 触发

- [ ] **TC-START-001** 触摸按键触发开始  
  操作步骤: Mainboard 上按下 TOUCH_START 按键  
  预期现象: `MySysCfg.start_status = 1`，Data_Transmit 线程进入 step0 发送流程  
  验证方式: 检查 `touch_task.c` 中 TOUCH_START 的短按事件处理

- [ ] **TC-START-002** Step0: Mainboard 发送开始指令（retry=1）  
  操作步骤: `start_status=1` 且 `send_step_nums==0` 且 `sensor_start_cmd_ack==0`  
  预期现象: Mainboard 通过 Pipe1 向 Sensor 发送 `FRAME_NRF24_SEND_TO_SENSOR_START_CMD`（CMD=0x02, DATA=start_status）  
  验证方式: 日志输出 "step1：mainboard发送开始指令到sensor成功!"

- [ ] **TC-START-003** Sensor 收到开始指令并回复 ACK（retry=5）  
  操作步骤: Sensor 收到 CMD=0x02 的 ASK 帧  
  预期现象: `Record.nrf_rec_start_cmd = 1`，`Flag.start = start_status`，60ms 周期内发送 ACK 帧（最多 5 次）  
  验证方式: Sensor 日志输出 "Receive：接收到从主板发来的开始指令"；Mainboard 收到 ACK

- [ ] **TC-START-004** Mainboard 收到 Sensor 开始确认，step_nums→1  
  操作步骤: Mainboard 收到 Sensor 的 ACK 帧（CMD=0x02, STATUS=0x02）  
  预期现象: `Record.sensor_start_cmd_ack = 1`，`send_step_nums = 1`  
  验证方式: Mainboard 日志输出 "Receive: 接收到sensor的开始指令的响应"

- [ ] **TC-START-005** Step1: Mainboard 发送眼部状态指令（retry=1, 濒死状态）  
  操作步骤: `send_step_nums==1` 且 `sensor_wsrgb_cmd_ack==0`  
  预期现象: Mainboard 发送 `FRAME_NRF24_ASK_WS2812B_LEVEL_CMD`（CMD=0x04, DATA=eyes_rgb_level=0 濒死）  
  验证方式: 日志输出 "step2：mainboard发送眼部状态(濒死)指令到sensor成功"

- [ ] **TC-START-006** Sensor 收到眼部状态指令并回复 ACK（retry=5）  
  操作步骤: Sensor 收到 CMD=0x04 的 ASK 帧  
  预期现象: `Record.ws2812b_levle = *(CmdBuf + 6)`，`Flag.ws2812b_ack = 1`，WS2812B(PA11)最低亮度，OLED(PC10/PC11)黑屏  
  验证方式: Sensor 日志输出 "Receive：眼部状态指令(濒死)"

- [ ] **TC-START-007** Mainboard 收到眼部状态确认，step_nums→2  
  操作步骤: Mainboard 收到 Sensor 的眼部状态 ACK  
  预期现象: `Record.sensor_wsrgb_cmd_ack = 1`，`send_step_nums = 2`  
  验证方式: Mainboard 日志输出 "step2...成功"

- [ ] **TC-START-008** Step2: Mainboard 发送电机初始状态指令（retry=1）  
  操作步骤: `send_step_nums==2` 且 `sensor_motor_cmd_ack==0`  
  预期现象: Mainboard 发送 `FRAME_NRF24_ASK_MOTOR_STATUS_CMD`（CMD=0x05, DATA=motor_work_sta=0）  
  验证方式: 日志输出 "step3：mainboard发送电机初始状态指令到sensor成功"

- [ ] **TC-START-009** Sensor 收到电机指令并回复 ACK（retry=5）  
  操作步骤: Sensor 收到 CMD=0x05 的 ASK 帧  
  预期现象: `Record.motor_work_sta = *(CmdBuf + 6)`，`Flag.motor_ack = 1`  
  验证方式: Sensor 日志输出 "Receive：电机工作模式指令"

- [ ] **TC-START-010** Mainboard 收到电机确认，step_nums→3，进入 CPR 业务循环

## 5. 按压数据采集

### 5.1 ADC128S 薄膜压力传感器

- [ ] **TC-PRESS-001** ADC128S 各通道读取  
  操作步骤: 调用 `adc128s102_read_raw(Channel_0, &value)` 读取压力通道  
  预期现象: 返回 `RT_EOK`，value 为 0~4095 范围内的 ADC 原始值  
  验证方式: 用万用表比对 ADC 值与实际电压对应关系

- [ ] **TC-PRESS-002** 5个方位触点检测  
  操作步骤: 分别按压上/中/下/左/右五个方位  
  预期现象: 对应通道的 ADC 值超过阈值，判定该触点被触发  
  验证方式: 读取各通道 ADC 值，检查是否超过阈值

- [ ] **TC-PRESS-003** 触点位置通过 nRF24L01 上报  
  操作步骤: 按压某一方位触发 ADC  
  预期现象: `body_led_type` 更新为对应方位值（1~7），通过 nRF 发送给 Mainboard  
  验证方式: Mainboard 日志输出按压位置数据

### 5.2 光栅板数据接收（UART2）

- [ ] **TC-PRESS-004** UART2 接收按压脉冲增量帧  
  操作步骤: 光栅板每 100ms 发送 TYPE=0x01 的 8 字节帧  
  预期现象: Sensor UART2 状态机成功解析帧头 0xAA → LEN=0x04 → 数据 → 校验 → 帧尾 0x55  
  验证方式: 日志输出无校验错误，`g_raster_press_cumulative` 正确累加

- [ ] **TC-PRESS-005** 按压深度计算  
  操作步骤: 收到脉冲增量 +5 后  
  预期现象: `g_raster_press_cumulative += 5`，`g_raster_press_depth_01mm = cumulative * 5 = 25` (0.1mm)  
  验证方式: 检查 `process_realtime_frame()` 中的计算逻辑

- [ ] **TC-PRESS-006** UART2 帧同步恢复（残帧处理）  
  操作步骤: 在数据域中插入帧头 0xAA  
  预期现象: 状态机检测到异常，回到 `PARSE_WAIT_LEN` 重新同步  
  验证方式: 日志无死锁，后续正常帧可正确解析

- [ ] **TC-PRESS-007** UART2 帧解析超时保护  
  操作步骤: 发送半帧后停止，等待超过 50ms  
  预期现象: `parse_state` 强制重置为 `PARSE_WAIT_HEAD`  
  验证方式: 后续发送完整帧可正常解析

- [ ] **TC-PRESS-008** UART2 循环队列满时丢弃  
  操作步骤: 快速发送大量数据导致循环队列满  
  预期现象: 队列满时新数据被丢弃，打印 "UART2 Queue Full! Data Lost"  
  验证方式: 日志输出警告，系统不崩溃

### 5.3 按压频率计算

- [ ] **TC-PRESS-009** 按压频率计算（Calculator_Process）  
  操作步骤: 连续两次按压（方向从 0→1），间隔 500ms  
  预期现象: `freq_10x = 600000 / 500 = 1200`（即 120.0 次/分）  
  验证方式: 检查 `app_calculator.c` 中 `s_press_records[s_press_count].freq_10x`

- [ ] **TC-PRESS-010** 按压事件检测（下压开始）  
  操作步骤: press_dir 从 0 变为 1  
  预期现象: `s_press.in_press_cycle = 1`，记录 `press_start_tick`  
  验证方式: 调试检查 `s_press` 状态变化

- [ ] **TC-PRESS-011** 按压事件检测（回弹→静止=按压结束）  
  操作步骤: press_dir 依次从 1→-1→0  
  预期现象: 检测到回弹后静止，记录本次按压（深度、频率、是否过深/不足）  
  验证方式: `s_press_count` 增加 1，`s_press_records` 中记录正确的 depth 和 freq

- [ ] **TC-CALC-005** 按压频率外判定

- [ ] **TC-CALC-008** 5循环内/外按压数

## 14. 容错与边界测试

### 14.1 连接建立容错

- [ ] **TC-ERR-001** Sensor 连接请求无限重试  
  操作步骤: Mainboard 不上电，Sensor 上电  
  预期现象: Sensor 每 500ms 发送连接请求，无上限，不会崩溃  
  验证方式: 运行 10 分钟以上无异常

- [ ] **TC-ERR-002** Remote 连接请求无限重试  
  操作步骤: Mainboard 不上电，Remote 上电  
  预期现象: Remote 每 150ms 发送连接请求，无上限  
  验证方式: 运行 10 分钟以上无异常

- [ ] **TC-ERR-003** Mainboard ACK 丢失重试  
  操作步骤: Sensor 收到 Mainboard 的开始指令后，故意不回复 ACK  
  预期现象: Mainboard 的 `send_step_nums` 不推进，Data_Transmit 线程持续重发（retry=1 每 50ms）  
  验证方式: 日志持续输出 step1 发送

### 14.2 数据传输容错

- [ ] **TC-ERR-004** CRC 错误帧丢弃  
  操作步骤: 发送 CRC 错误的 nRF24L01 帧  
  预期现象: 帧被丢弃，不触发业务逻辑  
  验证方式: 日志输出 "CRC Check FAILED"

- [ ] **TC-ERR-005** UART2 帧解析死锁保护  
  操作步骤: 发送不完整帧后停止通信  
  预期现象: 50ms 超时后自动重置解析状态机  
  验证方式: 后续通信正常

- [ ] **TC-ERR-006** UART2 循环队列溢出  
  操作步骤: 光栅板以极高速率发送数据  
  预期现象: 队列满时丢弃新数据，打印告警  
  验证方式: 日志输出 "UART2 Queue Full!"

- [ ] **TC-ERR-007** Pipe 来源未知帧丢弃  
  操作步骤: Mainboard 收到非 Pipe1/Pipe2 来源的数据  
  预期现象: `src = SRC_UNKNOWN`，帧被丢弃不处理  
  验证方式: 日志无异常处理

### 14.3 硬件异常

- [ ] **TC-ERR-008** nRF24L01 SPI 链路故障  
  操作步骤: 拔掉 nRF24L01 模块后上电  
  预期现象: SPI 回环检测失败，日志输出错误但系统不崩溃  
  验证方式: 日志输出 "nRF24L01 check spi hardware false"

- [ ] **TC-ERR-009** MPU6050 I2C 通信异常  
  操作步骤: 拔掉 MPU6050 后上电  
  预期现象: 初始化失败但系统不崩溃  
  验证方式: 日志输出 MPU6050 初始化错误

- [ ] **TC-ERR-010** ADC128S SPI 通信异常  
  操作步骤: 拔掉 ADC128S 后  
  预期现象: ADC 读取返回错误，联合判别可能失效但系统不崩溃  
  验证方式: 日志输出 ADC 读取错误

### 14.4 有线/无线切换

- [ ] **TC-ERR-011** RS485 有线连接检测  
  操作步骤: 连接 RS485 线缆  
  预期现象: `Record.wired_connect_flag = 1`，nRF24L01 可被 suspend  
  验证方式: 检查连接状态切换逻辑

- [ ] **TC-ERR-012** 有线模式下 Remote 仍可用  
  操作步骤: Sensor 通过 RS485 与 Mainboard 通信  
  预期现象: Mainboard 仍通过 nRF24L01 与 Remote 通信（Remote 不参与有线连接）  
  验证方式: Remote 正常接收 Mainboard 反馈

### 14.5 并发访问保护

- [ ] **TC-ERR-013** nRF24L01 硬件互斥锁  
  操作步骤: Decode_entry 和 Data_Transmit 同时需要访问 nRF24L01  
  预期现象: 通过 `nrf24_mutex` 串行化，不发生 SPI 总线冲突  
  验证方式: 日志无 SPI 通信异常

- [ ] **TC-ERR-014** UART2 循环队列互斥锁  
  操作步骤: UART2 中断回调写入队列，uart2_thread 读取队列  
  预期现象: 通过 `Uart2Buf.lock` 保护，无数据竞争  
  验证方式: 数据完整性验证
