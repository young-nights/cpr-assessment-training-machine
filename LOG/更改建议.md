## 1. 总体匹配情况

- **实时数据帧格式**：基本一致（8字节）
- **控制指令（Start/Stop）**：格式一致
- **深度计算**：完全一致（pulse × 5）
- **方向定义**：完全一致（-1/0/1）
- **业务流程**：核心匹配，但存在部分健壮性缺失

---

## 2. 存在的问题（必须修复）

### 严重问题（会影响通信稳定性）

**问题 1：Sensor 端帧解析状态机不够健壮**
- 当前仅简单判断 `parse_idx >= (parse_len + 1)` 就进入尾部检查
- 缺少最大长度保护、残帧处理、超时机制
- 风险：干扰数据会导致错误解析

**问题 2：Start 指令后双方累计值未同步清零**
- Raster 收到开始指令后会清零计数器
- Sensor 端 `g_raster_press_cumulative` / `g_raster_blow_cumulative` 未清零
- 导致新一次训练可能带入上一次残留数据

**问题 3：Raster 主循环中 `Delay_ms(100)` 是阻塞延时**
- 在裸机系统中会影响 UART 接收和中断响应
- 建议改为非阻塞（基于 `g_system_tick_ms`）

## 1. 当前状态总结

- 已实现：Sensor 板可发送模式切换指令（`CMD=0x11`），光栅板也能接收并调用 `switch_detect_mode()`。
- 未实现：**模式切换后没有实际影响**，吹气检测仍然**完全依赖光栅板自身的光电中断**。
- 核心问题：**Sensor 板的联合判别（ADC128S + MPU6050）目前是“单向无效”**，光栅板没有真正响应模式指令。

---

## 2. 存在的问题（优先级排序）

### 【高优先级 - 必须修复】

**问题 1：模式切换指令接收后未生效**  
- `switch_detect_mode()` 只修改了全局变量 `g_raster_detect_mode`，但 `main.c` 主循环和中断处理**完全没有使用这个变量**。
- 导致 Sensor 板判别出“吹气”后，光栅板依然按老逻辑运行。

**问题 2：吹气触发逻辑过于简单**  
- 当前只看 `if (direction_blow != 0)` 就发 `TYPE=02`，没有结合 Sensor 板的联合判别结果。
- 容易出现：轻微抖动误判为吹气，或真实吹气但幅度小（delta≈0）时完全不触发。

**问题 3：模式变量未被实际使用**  
- `g_raster_detect_mode` 定义了三种状态（IDLE / PRESSURE / BLOW），但目前只有定义，没有决策逻辑。

---

### 【中优先级 - 强烈建议】

**问题 4：吹气/按压优先级不清晰**  
- 当前吹气优先级高于按压，但没有明确的“模式锁定”机制，容易在动作交替时抖动切换。

**问题 5：文档与代码匹配度低**  
- `业务需求.md` §1.4 和 §3.4 详细描述了三路联合判别方案，但光栅板实现不完整。

---

```c
extern volatile raster_detect_mode_t g_raster_detect_mode;

## 3. 需要优化的点（强烈建议）

### 高优先级优化

1. **Sensor 端 `uart2_protocol.c` 状态机增强**
2. **Start 指令处理时 Sensor 端强制清零**
3. **Raster 端发送逻辑增加最小间隔保护**
4. **统一函数命名**：`USART1_SendPulseDir` → `USART1_SendRealtimeData`

### 中优先级优化

- 清理 Raster 板遗留的旧变量（`depth_count`、`direction`）
- Sensor 端增加帧丢失统计和日志
- Raster 端在 `RASTER_IDLE` 时停止发送无用 0 帧

```


### 3.2 修改 main.c 主循环（核心修改）

```C
case RASTER_ACTIVE:
{
    if ((g_system_tick_ms - last_send_tick) >= 100)
    {
        last_send_tick = g_system_tick_ms;

        delta_press = (int16_t)(depth_count_press - prev_press);
        delta_blow  = (int16_t)(depth_count_blow - prev_blow);
        prev_press = depth_count_press;
        prev_blow  = depth_count_blow;

        /* ==================== 核心修改：使用模式变量 ==================== */
        if (g_raster_detect_mode == RASTER_DETECT_BLOW || direction_blow != 0)
        {
            /* 吹气模式优先，或光电已检测到吹气运动 */
            USART1_SendRealtimeData(delta_blow, direction_blow, 0x02);
        }
        else
        {
            /* 默认或按压模式 */
            USART1_SendRealtimeData(delta_press, direction_press, 0x01);
        }
    }
    break;
}
```


### 3.3 增强 switch_detect_mode()（app_message.c）

```C
static void switch_detect_mode(uint8_t mode_code)
{
    switch (mode_code)
    {
        case CMD_ACTIVATE_PRESSURE:
            g_raster_detect_mode = RASTER_DETECT_PRESSURE;
            // 清零吹气计数，专注按压
            depth_count_blow = 0;
            direction_blow = 0;
            break;

        case CMD_ACTIVATE_BLOW:
            g_raster_detect_mode = RASTER_DETECT_BLOW;
            // 清零按压计数，专注吹气
            depth_count_press = 0;
            direction_press = 0;
            break;

        case CMD_IDLE_PRESSURE:
            g_raster_detect_mode = RASTER_DETECT_IDLE;
            break;

        default:
            break;
    }
}
```


4. 修改完成后预期效果

Sensor 板通过 ADC + MPU6050 联合判别 → 发送模式切换指令
光栅板收到指令 → 切换内部模式 → 优先上报对应 TYPE（01 或 02）
吹气检测更可靠，不再仅依赖光电传感器
