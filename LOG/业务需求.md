## 1. Sensor 板业务流程规范

### 1.1 上电初始化与自检流程

Sensor 板上电后按以下顺序完成外设初始化：

| 序号 | 外设/模块 | 接口 | 初始化内容 |
|------|-----------|------|-----------|
| 1 | STM32 系统时钟 | 内部 | 配置时钟树、GPIO、NVIC |
| 2 | UART2 (115200) | 串口 | 光栅板通信，配置中断接收、循环队列 |
| 3 | UART3 | 串口 | 调试/扩展通信 |
| 4 | nRF24L01 | SPI | 无线模块初始化、地址配置、频道配置、PRX/PTX 模式设置 |
| 5 | RS485 | UART | 有线通信备用，Modbus 从机初始化 |
| 6 | MPU6050 | I2C | 头部上仰角度检测，校准零点 |
| 7 | ADC128S102CIMTX | SPI | 薄膜压力传感器 ADC 检测（按压点位判断：上/中/下/左/右五个方位 + 气道开启 LED + 吹气进胃 LED） |
| 8 | STM32 内置 ADC | 片内 | 肩部震动检测（压电陶瓷片触发检测） |
| 9 | CC6201 霍尔传感器 | GPIO | 异物检测输入引脚配置 |
| 10 | WS2812B 眼灯 | PA11 (PWM) | 白光灯珠初始化，默认关闭 |
| 10b | OLED 眼屏 (0.66寸) | PC10 (SDA) / PC11 (SCL) | I2C OLED 初始化，默认黑屏 |
| 11 | 空心杯电机 | PWM | 颈动脉模拟 PWM 输出，默认关闭 |
| 12 | MPU6050 校准 | I2C | 加速度计/陀螺仪零偏校准 |

**自检结果**：
- 各外设初始化成功/失败状态记录到日志
- 关键外设（nRF24L01、MPU6050）失败时 LED 告警

### 1.2 连接建立流程

```
Sensor 板                                    Mainboard 板
    │                                            │
    │  [初始化完成，进入未连接状态]                  │
    │                                            │
    │── ASK_CONNECT (Pipe1, 每500ms) ────────────►│
    │   持续重试，无上限                            │
    │                                            │
    │◄── ACK_CONNECT (Pipe1, 重试3次) ────────────│
    │                                            │
    │  [nrf_if_connected = 1]                     │
    │  [连接建立完成，进入业务运行状态]              │
    │                                            │
```

**nRF24L01 帧结构**：

所有 nRF24L01 通信均使用统一帧格式，详细协议定义见 `cpr_business_framework.md §5.1`：

```
┌────────┬────────┬──────┬────────────────┬──────┬────────┬──────────┬──────┐
│ HEAD1  │ HEAD2  │ LEN  │   设备编码     │ 命令 │ 命令   │ 参数列表 │ CRC  │
│ 0x55   │ 0xAA   │ 1B   │ DEVICE_ID (2B) │ 类型 │ 状态   │ DATA     │ 2B   │
└────────┴────────┴──────┴────────────────┴──────┴────────┴──────────┴──────┘
```

- **帧头**：`0x55 0xAA`，固定标识
- **LEN**：覆盖区域 = 设备编码(2B) + 命令类型(1B) + 命令状态(1B) + 参数列表(NB)，即 `LEN = 4 + data_len`
- **设备编码**：2 字节，`DEVICE_SENSOR_ID = 0x0005` / `DEVICE_REMOTE_ID = 0x0004`
- **命令类型**：`FRAME_TYPE_ACT=0x31(动作) / FRAME_TYPE_SET=0x32(设置) / FRAME_TYPE_GET=0x33(获取) / FRAME_TYPE_POST=0x66(上报)`
- **命令状态**：`FRAME_STATE_ASK=0x01(请求) / FRAME_STATE_ACK=0x02(应答) / FRAME_STATE_ERR=0x00(出错)`
- **参数列表**：0~24 字节的命令参数
- **CRC**：CRC16-Modbus 校验，计算范围从 LEN 字节开始到参数列表末尾

**握手协议细节（源码实证）**：

**Step 1** — Sensor 发送连接请求（每 500ms 重试，无上限）：

Sensor 切换到 PTX 模式，通过 Pipe1 发送，发送后切回 PRX 等待 ACK：
```
源码: nrf24l01_order_to_pipe(_nrf24, Order_nRF24L01_ASK_Connect_Control_Panel, NRF24_PIPE_1)
帧内容: 55 AA 04 00 05 31 01 01 [CRC_H] [CRC_L]
        │  │  │  │  │  │  │  │
        │  │  │  │  │  │  │  └─ DATA[0] = 0x01 (FRAME_NRF24_ASK_CONNECT_PANEL_CMD)
        │  │  │  │  │  │  └─ CMD_STATUS = 0x01 (FRAME_STATE_ASK 请求)
        │  │  │  │  │  └─ CMD_TYPE = 0x31 (FRAME_TYPE_ACT)
        │  │  │  │  └─ DEVICE_ID_L = 0x05
        │  │  │  └─ DEVICE_ID_H = 0x00 (DEVICE_SENSOR_ID = 0x0005)
        │  │  └─ LEN = 0x04 (4 + data_len(1) = 5? 实际为 ID(2)+TYPE(1)+STATUS(1)+DATA(1)=5，但代码写 LEN=4+data_len)
        │  └─ HEAD2 = 0xAA
        └─ HEAD1 = 0x55
```

**Step 2** — Mainboard 接收并识别来源：

Mainboard 处于 PRX 模式，通过 Pipe1 接收。解码时校验帧头 `55 AA`，读取 LEN，校验 CRC，然后调用：
```
源码: nrf24l01_protocol_operation(CMD_buffer, SRC_FROM_SENSOR)
解析: cmd_type = *(CmdBuf + 3) = 0x31 (FRAME_TYPE_ACT)
      cmd      = *(CmdBuf + 5) = 0x01 (FRAME_NRF24_CONNECT_CTRL_PANEL_CMD)
```

**Step 3** — Mainboard 处理连接请求：
```
源码: Record.sensor_connect_pending = 1;
      Record.sensor_connected = 1;
      Record.last_sensor_heartbeat = rt_tick_get();
```

**Step 4** — Mainboard 回复连接 ACK（重试 3 次，间隔 50ms）：

Mainboard 切换到 PTX 模式，通过 Pipe1 发送，用 `nrf24l01_build_sensor_frame()` 构建帧（帧中 DEVICE_ID = 0x0005，即目标 Sensor 的地址）：
```
源码: nrf24l01_order_to_pipe(Order_nRF24L01_ACK_Connect_Control_Panel, NRF24_PIPE_1)
帧内容: 55 AA 04 00 05 31 02 01 [CRC_H] [CRC_L]
        │  │  │  │  │  │  │  │
        │  │  │  │  │  │  │  └─ DATA[0] = 0x01 (FRAME_NRF24_CONNECT_CTRL_PANEL_CMD)
        │  │  │  │  │  │  └─ CMD_STATUS = 0x02 (FRAME_STATE_ACK 应答)
        │  │  │  │  │  └─ CMD_TYPE = 0x31 (FRAME_TYPE_ACT)
        │  │  │  │  └─ DEVICE_ID_L = 0x05
        │  │  │  └─ DEVICE_ID_H = 0x00 (目标 Sensor 地址)
        │  │  └─ LEN = 0x04
        │  └─ HEAD2 = 0xAA
        └─ HEAD1 = 0x55
```

**Step 5** — Sensor 接收 ACK，连接建立：
```
源码: case FRAME_NRF24_ASK_CONNECT_PANEL_CMD:
        Record.nrf_if_connected = 1;  // 连接成功
```
Sensor 停止发送连接请求，进入业务运行状态。

**Step 6** — 用户按下 TOUCH_START，Mainboard 进入开始序列：
```
源码 (touch_task.c):
    MySysCfg.start_status = 1;

源码 (mainboard_nrf24l01_task.c):
    if(MySysCfg.start_status == 1 && send_step_nums == 0 && Record.sensor_start_cmd_ack == 0)
        nrf24l01_send_with_retry(_nrf24, Order_nRF24L01_SEND_To_Sensor_Start, NRF24_PIPE_1, 1)
```

**Step 7** — Mainboard 发送开始指令帧：
```
帧内容: 55 AA 05 00 05 31 01 02 01 [CRC_H] [CRC_L]
        │  │  │  │  │  │  │  │  │
        │  │  │  │  │  │  │  │  └─ DATA[1] = MySysCfg.start_status = 1 (已开始)
        │  │  │  │  │  │  │  └─ DATA[0] = 0x02 (FRAME_NRF24_SEND_TO_SENSOR_START_CMD)
        │  │  │  │  │  │  └─ CMD_STATUS = 0x01 (FRAME_STATE_ASK 请求)
        │  │  │  │  │  └─ CMD_TYPE = 0x31 (FRAME_TYPE_ACT)
        │  │  │  │  └─ DEVICE_ID = 0x0005 (Sensor)
        │  │  └─ LEN = 0x05 (4 + data_len(2))
```

**Step 8** — Sensor 接收开始指令并回复 ACK（重试 5 次）：
```
源码 (sensor_nrf24l01_message.c):
    case FRAME_NRF24_ACK_START_CMD:   // 0x02
        Record.nrf_rec_start_cmd = 1;
        Flag.start = *(CmdBuf + 6);   // 读取 start_status

源码 (sensor_nrf24l01_task.c):
    if(Record.nrf_rec_start_cmd == 1)
        nrf24l01_send_with_retry(_nrf24, Order_nRF24L01_ACK_Start_Cmd, NRF24_PIPE_1, 5)

Sensor 回复 ACK 帧:
55 AA 04 00 05 31 02 02 [CRC_H] [CRC_L]
                   │  │  └─ DATA[0] = 0x02 (FRAME_NRF24_ACK_START_CMD)
                   │  └─ CMD_STATUS = 0x02 (FRAME_STATE_ACK 应答)
```

**Step 9** — Mainboard 接收 Sensor 的开始确认：
```
源码: case FRAME_NRF24_SEND_TO_SENSOR_START_CMD:  // 0x02
        Record.sensor_start_cmd_ack = 1;
        send_step_nums = 1;  // 进入下一步(WS2812灯控制)
```

> ⚠️ **注意**：Sensor 和 Mainboard 的 nRF24L01 均支持 PTX/PRX 动态切换。Sensor 在发送连接请求后立即切回 PRX 打开接收窗口等待 ACK。Mainboard 默认处于 PRX 模式，需要发送时切换到 PTX。

### 1.3 业务运行流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  接收开始指令  │────►│  意识/脉搏/  │────►│  按压数据采集  │────►│  停止/复位    │
│  状态初始化    │     │  异物/呼吸   │     │  + 吹气数据   │     │  数据清零     │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

**详细步骤**：

1. **接收开始指令**
   - 收到 `FRAME_NRF24_SEND_TO_SENSOR_START_CMD` 后，标志位置位
   - 设置模拟人默认濒死状态：WS2812B 亮度 = 最低（瞳孔涣散），OLED 黑屏，空心杯电机使能 = 0（无颈动脉搏动）

2. **前置检查阶段**
   - **意识检测**：压电陶瓷片传感器触发检测（肩部拍打）
   - **脉搏检测**：空心杯电机状态检测（颈动脉触诊）
   - **异物检查**：CC6201 霍尔传感器检测
   - **呼吸检查**：通过光栅板数据辅助判断
   - **急救呼叫**：操作者口头呼叫确认

3. **按压数据采集阶段**
   - ADC128S102CIMTX 检测薄膜压力传感器：5 个按压方位（上/中/下/左/右）+ 气道开启 LED 位 + 吹气进胃 LED 位，ADC 值超过阈值 → 判定该点位被按压
   - 触点位置通过 nRF24L01 发送给 Mainboard
   - 按压频率计算：记录超过阈值的有效数据频次
   - 按压深度通过 UART2 接收光栅板计算结果
   - 颈动脉被动搏动频率与按压频率同步

4. **吹气数据采集阶段**
   - 潮气量数据通过 UART2 接收光栅板计算结果
   - MPU6050 检测头部上仰角度

5. **停止**
   - 收到 Mainboard 停止指令后，停止接收按压/吹气数据
   - 根据 Mainboard 指令控制眼灯状态

6. **复位**
   - 收到 Mainboard 复位指令后，所有数据清零
   - 回到初始状态，等待新的开始指令

### 1.4 按压/吹气三路信号联合判别方案

> **新增于 2026-04-29**：利用 Sensor 板外挂的 ADC128S 压力传感器和 MPU6050 姿态角，辅助光电传感器判别是按压还是吹气。

#### 1.4.1 物理特征差异

| 动作 | 栅格条方向 | 胸腔状态 | ADC128S 压力传感器 | MPU6050 头部姿态 |
|------|-----------|---------|-------------------|-----------------|
| **按压** | ↓ 向下 | 压缩 | **有压力**（超过阈值） | 头部基本不动（或微下压） |
| **吹气** | ↑ 向上 | 鼓起 | **无压力**（低于阈值） | **头部上仰**（pitch 角增大） |

#### 1.4.2 判别流程

```
光电传感器(ST130B) 检测到栅格条运动（中断触发）
        │
        ▼
  同时读取两路辅助信号
  ┌─────────────────┐   ┌─────────────────┐
  │ ADC128S 压力值   │   │ MPU6050 pitch 角 │
  └────────┬────────┘   └────────┬────────┘
           │                     │
           ▼                     ▼
    压力 > 阈值?           pitch ≥ +15° 且
                           变化速率 ≥ 30°/s 且
                           持续 ≥ 100ms?
           │                     │
      ┌────┴────┐           ┌───┴───┐
      │YES      │NO         │YES    │NO
      ▼         ▼           ▼       ▼
    按压    可能吹气      确认吹气  待确认/丢弃
```

#### 1.4.3 判别组合表

| ADC128S 压力 | MPU6050 上仰 | 判定结果 | Sensor→光栅板指令 |
|-------------|-------------|---------|-------------------|
| ✅ 有 | ❌ 无 | **按压** | activate 压力 |
| ❌ 无 | ✅ 有 | **吹气** | idle 压力 + activate 吹气 |
| ❌ 无 | ❌ 无 | 待确认/误触发 | 丢弃（栅格回弹抖动） |
| ✅ 有 | ✅ 有 | 冲突/异常 | **按压优先**（压力信号更可靠） |

#### 1.4.4 MPU6050 头部上仰判定细化条件

| 参数 | 默认值 | 说明 |
|------|--------|------|
| pitch 角阈值 | ≥ +15° | 头部上仰超过此角度视为有效上仰 |
| pitch 变化速率 | ≥ 30°/s | 上仰动作应在 0.5s 内完成，排除缓慢晃动 |
| 确认窗口 | 50ms | 光电触发后 50ms 内采样 pitch 值 |
| 持续时间 | ≥ 100ms | pitch 需持续超阈值 ≥ 100ms 才判定为吹气上仰 |
| 零位标定 | 启动时自动 | 以启动时 pitch 为 0° 基准，补偿安装偏差 |

**参数可调说明**：

| 参数 | 调整方向 | 影响 |
|------|---------|------|
| PITCH_THRESHOLD_DEG | ↓放松 ↑严格 | 降低会增加灵敏度但可能误判 |
| PITCH_RATE_THRESHOLD | ↓放松 ↑严格 | 降低可检测更慢的上仰动作 |
| BLOW_CONFIRM_WINDOW_MS | ↑更宽容 | 光电触发后的采样窗口 |
| BLOW_HOLD_MS | ↓更快响应 ↑更可靠 | 上仰需持续的时间 |

### 1.5 颈动脉模拟状态机

颈动脉模拟由空心杯电机驱动，通过不同振动模式模拟三种临床状态：

| 训练阶段 | 颈动脉状态 | 搏动性质 | 电机控制 | 模拟的临床意义 |
|----------|-----------|---------|---------|---------------|
| 初始化状态（未开始按压） | 无搏动 | 无跳动 | 使能=0，电机静止 | 心脏停跳，血液循环停止 |
| 按压过程中 | 被动搏动 | 搏动频率与按压频率一致 | 使能=1，频率跟随按压 | 按压产生的人工血液循环 |
| 抢救成功后 | 自主搏动 | 恢复规律的自主跳动 | 使能=1，固定频率自激 | 自主循环恢复（ROSC），患者获救 |

**状态切换逻辑**：
- `开始指令接收` → 电机使能=0（初始化/无搏动）
- `按压开始` → 电机使能=1，振动频率 = 按压频率（被动搏动）
- `抢救成功判定` → 电机使能=1，切换为固定频率自主振动（ROSC）

### 1.6 眼部板状态显示（OLED + WS2812B）

眼部板由 0.66 寸 OLED 和 WS2812B 两个组件协同显示眼睛状态。OLED 不显示复杂图案，仅通过亮灭区域表达状态；WS2812B 始终发出白光。

**硬件引脚**：

| 组件 | 引脚 | 接口 |
|------|------|------|
| WS2812B | PA11 | PWM 输出 |
| OLED SDA | PC10 | I2C 数据线 |
| OLED SCL | PC11 | I2C 时钟线 |

**两种状态**：

| 状态 | WS2812B | OLED |
|------|---------|------|
| **濒死** | 亮度调至最低 | 黑屏（全灭） |
| **正常** | 白灯全亮 | 屏幕中间有部分圆形区域为黑色，其余部分显示白色 |

**状态切换逻辑**：
- `开始指令接收` → 默认濒死状态（WS2812B 最低亮度 + OLED 黑屏）
- `抢救成功判定 (ROSC)` → 切换为正常状态（WS2812B 白灯全亮 + OLED 白底黑圆）
- `复位指令` → 回到濒死状态

> WS2812B 和 OLED 由同一条 Mainboard 指令（`FRAME_NRF24_ASK_WS2812B_LEVEL_CMD` 0x04）联动控制，不再区分多档亮度，仅区分濒死/正常两种状态。

### 1.7 触点检测与频率计算

**ADC 阈值判断逻辑**：
- ADC128S102CIMTX 多通道采集，每个通道对应一个薄膜压力传感点位（上/中/下/左/右五个按压方位 + 中偏上气道开启 LED + 中偏下吹气进胃 LED）
- 当 ADC 采样值超过预设阈值 → 判定该触点被按压
- ADC 采样值本身**不参与**按压深度计算，仅用于判断触点是否触发
- 按压深度由光栅板通过 UART2 独立计算

**频率计算**：
- 记录连续触发的有效数据（超过阈值的采样）
- 两个有效数据之间的时间间隔 → 按压频率 = 60000 / interval_ms（次/分）
- 频率通过 nRF24L01 实时传递给 Mainboard

### 1.7 光栅板数据接收与处理

- Sensor 板通过 UART2 (115200bps) 连接光栅板
- 接收光栅板原始脉冲增量帧（8字节，每100ms）：脉冲计数增量、方向、类型
- Sensor 板累加脉冲增量并计算深度：`depth_01mm = cumulative × 5`
- **成绩计算全在 Sensor 板完成**：事件检测、深度判断、频率计算、循环统计、成绩组装
- 成绩通过 nRF24L01 上报给 Mainboard
- 光栅板收到停止指令后直接返回待机，不再发送成绩帧

## 3. 光栅板业务流程规范

### 3.1 硬件结构说明

- **主控**：STM8S 裸机（无 RTOS），纯中断驱动
- **光电传感器**：ST130B × 4（PCB 两端各 2 个）
- **通信**：UART1 (115200bps, 8N1) 连接 Sensor 板 UART2

**栅格条运动逻辑**：
- PCB 板竖直固定在模拟人体内，栅格条在中间沿竖直方向运动
- **按压动作**：按压胸部 → 栅格条**向下**运动 → 释放后弹簧回弹
- **吹气动作**：吹气使胸腔鼓起 → 栅格条**向上**运动 → 泄气时胸腔塌陷 → 栅格条**向下**回到初始

### 3.2 按压与吹气的运动方向区分机制

通过光电传感器的安装位置区分：
- 按压和吹气产生相反方向的栅格条运动
- 光栅编码器 A/B 相序判断运动方向
- B 相高电平 = 正向（下压/鼓起），B 相低电平 = 反向（回弹/塌陷）
- 按压方向 = 下压（正向），吹气方向 = 向上（鼓起）

### 3.3 成绩数据计算职责边界

**光栅板职责**（纯数据采集）：

| 数据项 | 说明 |
|--------|------|
| 脉冲计数累加 | 中断驱动正交解码，累加 `depth_count_press` / `depth_count_blow` |
| 方向判断 | 通过 A/B 相序判断方向 `direction_press` / `direction_blow` |
| 脉冲增量发送 | 每 100ms 发送自上次以来的脉冲增量（int16_t） |

**Sensor 板接管的计算**（原光栅板职责 + 原有职责）：

| 数据项 | 计算方法 | 说明 |
|--------|---------|------|
| 脉冲→深度 | depth_mm = cumulative × 5 | 累加脉冲增量后乘以每脉冲 0.1mm 数 |
| 按压频率 | freq = 60000 / interval_ms | 相邻按压间隔 |
| 标准频率外次数 | interval < 500ms 或 > 600ms | 逐次检测 |
| 按压正确率 | press_correct × 100 / press_total | 百分比整数运算 |
| 按压错误总数 | too_deep + too_shallow + position_err + no_rebound | 汇总 |
| 按压正确/错误计数 | 深度在 PRESS_DEPTH_MIN~MAX 范围 | 逐次判定 |
| 按压不足/过大 | depth < 500 / depth > 600 (0.1mm) | 逐次判定 |
| 少按/多按 | 每循环与标准30次差额累计 | 循环边界计算 |
| 回弹判定 | 按压后是否检测到反向脉冲 | 新按压开始时检查前次是否回弹 |
| 吹气平均时间 | 每次充气→泄气的时间差取平均 | ms单位 |
| 循环间间断时间 | 上次按压结束→本次按压开始的间隔 | 取平均，ms单位 |
| 吹气正确率 | blow_correct × 100 / blow_total | 百分比整数运算 |
| 吹气错误总数 | blow_too_much + blow_too_little | 汇总 |
| 潮气量判定 | 与 BLOW_DEPTH_MIN/MAX 比较 (500~600, 0.1mm) | 逐次判定 |
| 平均潮气量 | tidal_sum / blow_depth_cnt | 0.1mm单位，1mm≈100ml |
| 循环统计 | 30按压+2吹气 = 1循环 | 区分5循环内外 |
| 实际用时 | 开始到结束的总时间 | 秒单位 |
| 急救结果 | 至少1个完整循环且按压正确率≥70% | 0=失败, 1=成功 |
| 按压位置 | 需要 MPU6050 角度数据 | Sensor 板 MPU6050 |
| 头部上仰判定 | 需要 MPU6050 角度数据 | Sensor 板 MPU6050 |
| 震动检测结果 | 需要压电陶瓷片 ADC | Sensor 板 STM32 内置 ADC |
| 异物检测 | 需要 CC6201 霍尔传感器 | Sensor 板 CC6201 |

### 3.4 通讯协议重构要求

**实时数据帧（光栅板 → Sensor，每 100ms，8字节）**：

```
Byte:  [0]    [1]    [2]    [3]    [4]    [5]    [6]    [7]
       0xAA   0x04   TYPE   CNT_H  CNT_L  DIR    CHK    0x55
       帧头   长度   类型   计数H  计数L  方向   校验   帧尾
```

- 帧头 0xAA + 帧尾 0x55 用于帧同步
- 长度字段 0x04 = 数据域长度（TYPE+CNT_H+CNT_L+DIR = 4字节）
- 类型：0x01=按压数据，0x02=吹气数据
- 脉冲计数：int16_t，自上次发送以来的脉冲增量（正=正向，负=反向）
- 方向：-1（回弹/泄气）/ 0（静止）/ 1（下压/充气）
- 校验：Byte[0]~Byte[5] 累加和

**Sensor 板收到后处理**：
- 累加脉冲增量：`cumulative += pulse_count`
- 计算深度：`depth_01mm = cumulative × 5`（每脉冲 0.5mm = 5 × 0.1mm）
- 使用深度值进行事件检测和成绩计算

**停止指令（Sensor → 光栅板，6字节）**：

```
Byte:  [0]    [1]    [2]    [3]    [4]    [5]
       0xAA   0x02   0x03   0xFF   CHK    0x55
       帧头   长度   命令   停止   校验   帧尾
```

- 帧头 0xAA + 帧尾 0x55 用于帧同步
- 长度字段 0x02 = 数据域长度（CMD+DATA = 2字节）
- 命令 0x03 = 停止指令, 数据 0xFF = 固定填充
- 校验: Byte[0]~Byte[3] 累加和
- 光栅板收到停止指令后直接返回待机状态（不再发送成绩帧）

**成绩计算**：
- 光栅板不再计算成绩，所有成绩计算由 Sensor 板完成
- Sensor 板使用已累计的原始脉冲数据进行最终成绩计算
- 成绩通过 nRF24L01 无线链路上报给 Mainboard

**Sensor → 光栅板 模式切换指令（6字节，新增于 2026-04-29）**：

```
Byte:  [0]    [1]    [2]    [3]    [4]    [5]
       0xAA   0x02   0x11   DATA   CHK    0x55
       帧头   长度   模式   数据   校验   帧尾
```

| DATA 值 | 宏定义 | 含义 | 触发条件 |
|---------|--------|------|---------|
| 0x01 | CMD_ACTIVATE_PRESSURE | 进入按压检测模式 | ADC128S 压力超过阈值 |
| 0x02 | CMD_IDLE_PRESSURE | 退出按压检测模式（空闲） | 无压力且非吹气 |
| 0x03 | CMD_ACTIVATE_BLOW | 进入吹气检测模式 | MPU6050 上仰确认 + 无压力 |

- CMD=0x11 为模式切换类别，DATA 区分子指令
- 校验：Byte[0]~Byte[3] 累加和
- 光栅板收到模式切换指令后，更新 `g_raster_detect_mode` 变量。主循环中根据模式变量和光电编码器方向值联合决定发送 TYPE（0x01 按压 / 0x02 吹气）。进入新模式时自动清零旧模式的计数器残留。
- 状态变化时才发送，避免重复发送

**指令与数据位区分原则**：
- 帧头 0xAA + 长度字段区分实时帧（0x04）、停止指令帧（0x02, CMD≠0x11）和模式切换帧（0x02, CMD=0x11）
- CMD=0x11 时，DATA 字节区分模式：0x01=按压, 0x02=空闲, 0x03=吹气
- 帧头/帧尾对称（0xAA...0x55）确保帧同步可靠性

考核模式下，系统需要额外检测并记录以下操作步骤的执行情况：

1. **意识判断**：压电陶瓷片是否在规定时间内触发（肩部拍打检测）
2. **脉搏检查**：空心杯电机状态是否被读取（颈动脉触诊模拟）
3. **检查呼吸**：通过光栅板数据辅助判断施救者是否执行呼吸观察
4. **急救呼叫**：操作者口头呼叫确认（需按键确认或语音识别）
5. **清除异物**：CC6201 霍尔传感器从"有异物"状态变为"无异物"
6. **开放气道**：MPU6050 检测头部上仰角度是否达到标准
7. **急救前脉搏检查**：开始按压前是否检查脉搏
8. **急救后脉搏检查**：停止按压后是否检查脉搏
9. **急救前瞳孔检查**：开始急救前是否检查瞳孔状态
10. **急救后瞳孔检查**：急救结束后是否检查瞳孔状态

每项检查结果记录为"完成"或"未完成"，纳入最终成绩评定。
